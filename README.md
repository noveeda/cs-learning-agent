# CS Learning Agent

CS 전반의 이론·개념 학습을 돕는 에이전트형 학습 도구입니다.
학습 주제 선택과 맞춤형 커리큘럼 구성부터 설명·질의응답·시각화·소단원 평가·보충 학습까지 연결해,
학습자가 이해도를 확인하며 체계적으로 학습하도록 돕는 것을 목표로 합니다.

운영체제·네트워크·자료구조·알고리즘·데이터베이스·컴퓨터 구조 등 CS 전반을 학습 범위로 삼습니다.
채팅과 도식은 학습 과정에서 사용하는 수단이며, 핵심은 커리큘럼을 따라 배우고 이해도를 확인하며 다음 단원으로 진행하는 경험입니다.
현재는 이 흐름의 기반 기능을 구현한 로컬 개발용 프로토타입으로, 전체 학습 과정은 아직 완성되지 않았습니다.

## 대상과 우선순위

| 우선순위 | 학습자 | 집중할 학습 문제 |
| --- | --- | --- |
| 1 | 기초를 보완하는 취업 준비생 | 단편적으로 아는 개념을 연결하고 원리·차이·선택 이유를 자기 말로 설명하기 |
| 2 | 전공 수업을 공부하는 학생 | 수업에서 이해하지 못한 이론·개념을 설명과 예시로 보충하기 |
| 3 | CS를 처음 배우는 입문자 | 낯선 용어와 선수 개념을 익히고 기초부터 학습하기 |

## 목표 학습 흐름

다음은 구현 목표이며, 현재 제공되는 기능 전체를 뜻하지 않습니다.

1. **학습 주제 선택:** 공부할 부분을 직접 고릅니다. 정하지 못했다면 AI에게 추천받습니다.
2. **커리큘럼 구성:** AI가 선택한 주제의 학습 순서와 단원·소단원별 목표를 구성합니다.
3. **커리큘럼에 따른 학습:** 정해진 순서에 따라 소단원의 이론과 개념을 공부합니다.
4. **질의응답과 이해 보조:** 모르는 내용을 에이전트에게 질문하고, 설명이 어렵다면 도식 등 시각화 자료로 보충합니다.
5. **소단원 이해도 확인:** 소단원이 끝날 때마다 시험·확인 문제 등으로 이해했는지 점검합니다.
6. **보충 또는 다음 단원:** 이해가 부족하면 보충 학습과 재평가를 진행하고, 충분히 이해했다면 다음 단원으로 넘어가 반복합니다.

평가 문항 형식, 채점·통과 기준, 학습자가 진행 여부를 조정하는 방식은 후속 설계에서 구체화합니다.
AI의 평가만으로 이해를 확정하거나 단일 정답만으로 학습 완료를 판단하지 않도록 설계할 예정입니다.

## 구현 상태

### 현재 구현된 기반 기능

- 운영체제·자료구조·네트워크의 기본 개념 9개를 큰 범주 원 안에 개념 노드를 담는 로드맵에서 확인합니다. 점선은 명시된 다른 영역 간 연관 관계만 표시하고, 연결 이유를 상세에서 설명합니다. 같은 영역 내 학습 순서는 상세의 선수·후속 개념으로 안내합니다. 마우스 호버·키보드 초점 시 관련 개념과 연결선을 강조하며 클릭 선택은 유지합니다.
- 개념별 설명을 보고 학습을 시작하며, 미학습·학습 중·완료 상태를 직접 변경합니다.
- 개념별 대화를 자유 학습과 분리하고, 선택한 개념·상태·대화 연결을 같은 브라우저에서 복구합니다.
- 웹에서 질문하고 답변을 실시간으로 확인합니다.
- 모델이 `create_diagram` 도구를 호출해 SVG 도식을 만들거나 후속 질문에 맞춰 수정합니다.
- 백엔드에 대화와 도식 구조를 저장하고 새로고침·백엔드 재시작 후 복구합니다.
- 최근 문답과 선택한 도식 정보를 모델에 전달하고, 토큰 예산을 넘으면 오래된 문답부터 제외합니다.

예시 질문:

> 가상 메모리와 페이징은 어떤 관계야? 가상 페이지가 물리 프레임에 매핑되는 모습을 도식으로 설명해줘.

이 기능들은 목표 학습 흐름의 질의응답·이해 보조 기반입니다.
대화 본문·도식은 백엔드에 저장하고, 기본 로드맵의 선택·상태·개념별 대화 ID는 브라우저 localStorage에 저장합니다.
학습 상태는 사용자가 직접 표시하며, 자동 평가 결과나 AI가 생성한 커리큘럼 진도를 뜻하지 않습니다.
현재 화면은 디자인 시안을 바탕으로 구성했으며, 후속 수정에 따라 조정합니다.

로드맵은 사이드바의 **로드맵** 또는 `/#/roadmap`에서 엽니다. 개념 선택 후 **학습 시작**을 누르면
해당 개념의 질문이 채워진 학습 화면으로 이동합니다. 전송 버튼을 눌러야 모델 요청이 시작됩니다.
기존 개념은 **학습 이어가기**로 대화를 복구하며, 완료 상태는 재학습해도 유지합니다.
모바일은 그래프 대신 개념 목록을 제공하고 선택 시 하단 상세로 이동합니다.

로드맵 데이터는 같은 브라우저·접속 주소에서만 유지되며 기기 간 동기화는 제공하지 않습니다.
사이트 데이터를 지우면 로드맵 상태와 대화 연결이 초기화됩니다. 백엔드 대화 파일 자체는 삭제하지 않습니다.
저장 공간·권한 문제로 저장에 실패하면 안내를 표시하고 해당 변경을 적용하지 않습니다.
학습 중 **새 학습**은 현재 개념의 대화 연결만 새로 만들며, 사이드바 **학습하기**는 자유 학습을 엽니다.

### 단계별 커리큘럼 초안 생성

웹 상단의 **커리큘럼 초안**에서 주제·학습 목적·현재 수준을 입력합니다.
AI가 주제 범위와 수준에 따라 개요와 단원·소단원 수를 정합니다. 생성 상태는 다음 순서로 진행됩니다.

1. **개요 구성:** 학습 범위를 단원별로 이어서 구성하고 안정적인 단원 ID를 부여합니다.
2. **단원 생성:** 개요의 소단원마다 학습 목표를 작성합니다. 모델이 제목을 바꾸지 않도록 코드에서 원래 제목을 유지합니다.
3. **단원 검토:** 사실 오류, 필수 개념 누락, 선수 개념 순서와 중복을 확인합니다.
4. **전체 검토·보완:** 전체 주제의 범위 충족 여부를 검토하고 문제가 있는 단원만 보완한 뒤 다시 검토합니다.
5. **초안 완성:** 모든 소단원의 목표와 검토가 끝나고 보완 항목이 없을 때만 완료로 표시합니다.

AI의 자기 검토는 교육 내용의 정확성을 보장하지 않습니다. 실제 학습에 쓰기 전에 내용을 확인해야 합니다.

- [x] 주제·목적·현재 수준 입력, 개요와 단원별 생성
- [x] 전체 검토·부분 보완, 미완료 결과와 완료 초안 구분
- [x] 입력 토큰 실측, 모델 문맥 압축, 출력 잘림 시 작업 분할
- [x] 단계별 저장·일시 중단·재개·새로고침 및 백엔드 재시작 복구
- [ ] 사용자 검수: 학습 범위·순서·목표·보완 결과의 적절성

**컨텍스트 관리:** `/tokenize`에 실제 생성과 동일한 메시지·출력 schema 설명·채팅 템플릿 설정을 전달합니다.
서버의 `max_model_len`에서 입력 토큰과 안전 여유 256토큰을 뺀 나머지를 해당 호출의 최대 출력 예산으로 사용합니다.
고정 2,048토큰 출력 상한은 없습니다. 응답의 실제 입력 토큰과 추정치도 비교합니다.
이 예산은 교육 내용의 완성 분량이 아니라 한 번의 호출에 가능한 공간입니다.

입력과 여유분이 컨텍스트의 75%를 넘으면 지난 단원의 상세 목표·중간 상태를 단원 ID·제목·범위·소단원 개요로 압축합니다.
이는 별도 요약 모델 호출이 아닌 **구조화된 요약 뷰**입니다. 원본 단원과 목표는 저장된 체크포인트에 그대로 남습니다.
사용자의 요구와 현재 처리할 단원·소단원은 원문을 유지합니다. 압축 후 실제 토큰 수가 줄었을 때만 적용합니다.
75%와 256토큰은 운영상 초기 여유 설정이며 교육적 기준이 아닙니다.

한 단원의 생성이나 검토가 입력·출력 한도에 걸리면 소단원 단위로 나누어 다음 호출에서 이어갑니다.
개요가 잘리면 더 작은 단원으로 나누어 재요청합니다. 불완전한 JSON을 붙이거나 완료로 저장하지 않습니다.
최소 작업의 필수 문맥도 들어가지 않으면 결과를 보존하고 범위 조정이 필요하다고 표시합니다.
압축된 전체 검토에서는 다른 단원의 상세 내용이 생략될 수 있어 단원별 원문 검토도 별도로 수행합니다.

**검토 스트리밍과 반복 감지:** AI core는 단원·전체 검토 응답을 스트리밍으로 읽습니다.
웹 화면에는 검증을 마친 단계별 결과를 표시하며, 검토 JSON 조각을 그대로 노출하지 않습니다.
동일한 문제 항목 재출력, 32~256자 패턴의 3회 연속 반복, 256자 연속 공백을 감지하면 스트림을 닫습니다.
이는 운영상 반복 감지 기준이며 정상적인 장문 검토나 학습 단원 수를 제한하지 않습니다.
표현이 다른 의미상 반복까지 감지하는 기능은 아닙니다. 검토 중 수신 시 경과 시간도 확인해 300초를 넘으면 중단합니다.
반복·시간 초과 시 완료된 초안은 보존하고 재시도를 안내합니다. 체크포인트의 `usage`에 수신 문자 수와 경과 시간을 남깁니다.

검토 대상은 **제목·범위·학습 목표로 구성된 초안**입니다. 강의 본문의 수식·예제·상세 설명이 없다는 이유로 보완을 요구하지 않습니다.
명백한 사실 오류, 요청한 핵심 주제 누락과 학습을 막는 선수 순서를 점검합니다.
이전 피드백은 보완 단계에서 활용하되 새 검토 입력에서는 제외해 기존 지적을 그대로 반복할 가능성을 줄입니다.

**저장·재개:** 백엔드는 실행 디렉터리 기준 `data/curricula/{id}.json`에 생성 상태를 원자적으로 저장합니다.
위치는 `--curriculum.storage-dir=/절대/경로`로 지정합니다. 브라우저는 현재 작업 ID만 localStorage에 보관합니다.
`일시 중단`은 진행 중인 단계를 저장한 뒤 멈춥니다. 새로고침 후에는 `이어서 생성`으로 재개합니다.
네트워크 응답을 잃어도 버전 번호로 이미 저장된 단계를 중복 실행하지 않습니다.
동일 작업의 동시 요청은 거부하며, 단일 백엔드 프로세스용 저장소입니다.
`새 초안`은 새 작업을 시작하며 기존 서버 파일을 삭제하지 않습니다. 작업 목록 UI는 없습니다.
이 저장은 **생성 작업의 체크포인트**이며 학습자의 진도·평가 저장이 아닙니다.

기술적 보호 한도는 입력·출력 문자열당 300자, 모델 요청 timeout 300초, 백엔드 320초, 브라우저 330초입니다.
AI core의 `CURRICULUM_MAX_STEPS`(기본 100단계), `CURRICULUM_MAX_REPAIRS`(기본 3회 보완 순환)는 무한 작업을 막는 운영 설정입니다.
같은 단계가 3회 실패하거나 작업 한도에 도달하면 완료로 위장하지 않고 `확인 필요` 상태로 중단합니다.
일시적인 실패는 같은 작업에서 재시도할 수 있지만, `확인 필요` 작업은 부분 결과를 확인하고 범위를 조정해 새 작업을 시작해야 합니다.
각 호출은 기존 채팅과 AI core 프로세스의 실행 잠금을 공유합니다.

**LangGraph 1차 도입:** Python AI core의 단계 선택은 LangGraph `StateGraph`로 실행합니다.
저장된 `stage`에 따라 `outline`, `generate`, `review`, `final_review`, `repair` 중 하나의 노드를 실행하고,
다음 단계까지 자동 반복하지 않고 요청을 종료합니다. 저장 JSON의 전체 검토 단계 값은 기존 `final`을 유지합니다.
한 번의 `/step` 요청은 모델 호출을 최대 한 번만 수행하며, 다음 요청 전에 Spring이 결과를 저장하고 버전을 증가시킵니다.

외부 API·요청/응답 필드·JSON 저장 형식·모델 SDK·프롬프트·토큰 예산·재시도 한도는 유지합니다.
완료·확인 필요 상태와 작업 한도 도달 시에는 모델을 다시 호출하지 않습니다.
실패한 단계의 부분 변경은 마지막 유효 상태로 되돌리고, 호출량·오류 안내와 기존 재시도 횟수는 기록합니다.

LangGraph 전용 체크포인터·DB·노드 캐시·자동 재시도는 사용하지 않습니다.
Spring의 JSON 체크포인트가 기준이며 기존 파일을 변환할 필요가 없습니다.
재개는 마지막으로 저장된 단계부터 진행합니다. 모델 응답 후 Spring 저장 전에 프로세스가 종료되면
해당 단계가 다시 실행될 수 있으며, 생성 중이던 토큰을 그대로 이어받는 기능은 아닙니다.
LangGraph 영속 저장소 도입은 별도 후속 작업입니다. 문제 발생 시 이전 코드와 의존성으로 되돌려 기존 JSON을 계속 읽을 수 있습니다.

| API | 역할 |
| --- | --- |
| `POST /api/curriculum/draft` | `{topic, goal, level}`로 생성 작업 생성 |
| `GET /api/curriculum/draft/{id}` | 마지막 저장 상태 조회 |
| `POST /api/curriculum/draft/{id}/step` | `{version}`을 받아 다음 단계 실행·저장 |
| FastAPI `POST /curriculum/step` | 백엔드가 전달한 상태에서 최대 한 번 모델을 호출 |

| 코드 | 역할 |
| --- | --- |
| `frontend/src/CurriculumDraft.tsx` | 입력·진행 상태·부분 결과·일시 중단·재개 화면 |
| `frontend/src/curriculum.ts` | 생성·조회·단계 API와 시간 제한 처리 |
| `backend/src/main/java/com/csagent/backend/CurriculumController.java` | 요청 중계, 버전 기반 중복 실행 방지 |
| `backend/src/main/java/com/csagent/backend/CurriculumStore.java` | 원자적 체크포인트 저장·복구·동시 요청 잠금 |
| `ai-core/serving/curriculum.py` | 상태 전환, 실제 토큰 계산, 압축·분할 생성, 검토·보완 |

웹·백엔드·AI core 자체는 GPU를 요구하지 않지만, 실제 답변에는 별도로 실행 중인 모델 서버가 필요합니다.
모델의 가중치와 실행용 vLLM 환경은 저장소에 포함하지 않습니다.

### 1. 소스와 앱 의존성 설치

```bash
git clone https://github.com/noveeda/cs-learning-agent.git
cd cs-learning-agent
python3.12 -m venv ai-core/.venv
ai-core/.venv/bin/python -m pip install -r ai-core/requirements-web.txt
(cd frontend && npm ci)
```

이미 저장소와 가상환경이 있다면 clone과 가상환경 생성은 생략합니다.
이후 명령은 별도 안내가 없으면 **저장소 루트**에서 실행합니다.
Gradle 의존성은 첫 실행 때 다운로드합니다.

### 2. 모델 서버 준비

**이미 실행 중인 경우:** 다음 요청으로 모델 목록을 확인하고 3단계로 이동합니다.

```bash
curl --fail http://127.0.0.1:8000/v1/models
```

응답이 오더라도 도구 호출 설정과 `/tokenize` 지원이 필요합니다. AI core는 모델 목록의
`max_model_len`과 실제 입력 토큰 수를 사용하므로 일반적인 OpenAI 호환 서버만으로는 충분하지 않습니다.

**처음 준비하는 경우:** GPU 서버에서 모델용 환경을 별도로 준비합니다.
다음은 기존 2-GPU·32K 구성에 맞춘 실행 예시이며, 다른 GPU에서의 메모리·CUDA 호환성을 보장하는 설정은 아닙니다.

```bash
python3.12 -m venv "$HOME/.venvs/cs-vllm"
"$HOME/.venvs/cs-vllm"/bin/python -m pip install 'vllm==0.32.0'
"$HOME/.venvs/cs-vllm"/bin/vllm serve cyankiwi/Qwen3.5-27B-AWQ-4bit \
  --host 127.0.0.1 --port 8000 \
  --tensor-parallel-size 2 \
  --max-model-len 32768 \
  --max-num-seqs 1 \
  --gpu-memory-utilization 0.9 \
  --disable-custom-all-reduce \
  --enable-auto-tool-choice \
  --tool-call-parser qwen3_xml
```

첫 실행은 모델 다운로드와 초기화에 시간이 걸립니다. 기본 모델 캐시는 `~/.cache/huggingface/hub/`입니다.
위 명령은 포그라운드에서 실행하므로 해당 터미널을 유지합니다. 모델 목록 요청이 성공한 뒤 앱을 실행합니다.
`--disable-custom-all-reduce`는 기존 GPU 간 P2P 미지원 환경을 고려한 옵션입니다.
기존 구성에서는 CUDA graph를 사용하기 위해 `--enforce-eager`를 넣지 않습니다.
새 환경에서의 모델 설치·기동은 GPU 드라이버와 CUDA 조합을 별도로 확인해야 합니다.

### 3. 앱 실행

모델 서버 외에 **각각 별도 터미널**을 열고 저장소 루트에서 실행합니다.
이미 서비스가 실행 중이면 같은 포트에 중복 실행하지 않습니다.

```bash
# 터미널 1: Python AI core
cd ai-core
.venv/bin/python -m uvicorn serving.api:app --host 127.0.0.1 --port 8001
```

```bash
# 터미널 2: Spring Boot 백엔드
cd backend
./gradlew bootRun --args='--server.address=127.0.0.1'
```

```bash
# 터미널 3: React 개발 서버
cd frontend
npm run dev
```

브라우저에서 [학습 화면](http://localhost:5173)을 엽니다.
AI core 프로세스 상태는 `curl --fail http://127.0.0.1:8001/health`로 확인할 수 있습니다.
이 health 응답은 모델 연결이나 답변 생성 성공까지 검사하지 않습니다.

원격 서버에서 실행한다면 **내 PC의 터미널**에서 5173 포트만 전달합니다.
아래 사용자와 서버 주소는 실제 SSH 접속 정보로 바꿉니다.

```bash
ssh -N -L 5173:127.0.0.1:5173 사용자@서버주소
```

### 연결 설정과 CLI

| 설정 | 기본값·용도 |
| --- | --- |
| `VLLM_BASE_URL` | `http://127.0.0.1:8000/v1` — AI core의 모델 접속 주소 |
| `VLLM_MODEL` | 미설정 시 모델 목록의 첫 모델 사용 |

`application.yml`의 기존 `langchain4j` 모델 설정은 현재 `/api/chat` 요청 경로에서 사용하지 않습니다.

`ask.py`는 도구 없이 모델을 직접 호출하는 별도 예제입니다.

### API와 대화 저장

| API | 역할 |
| --- | --- |
| `POST /api/chat` | `{conversation_id, question, artifact_id?}`를 받아 NDJSON 이벤트 스트리밍 |
| `GET /api/conversations/{id}` | 저장된 대화와 도식 구조 복구 |
| `GET /api/artifacts/{id}` | 생성 SVG 조회 |

백엔드를 `backend/`에서 실행하면 대화는 `backend/data/conversations/{id}.json`에 저장됩니다.
SVG 파일은 `ai-core/outputs/diagrams/`에 저장되므로 둘 다 보존해야 대화와 도식 파일을 함께 복구할 수 있습니다.
브라우저는 대화 ID를 localStorage에 저장합니다. 새 학습은 새 ID를 만들며 기존 파일을 삭제하지 않습니다.
과거 대화 목록 UI는 없으므로 브라우저의 ID를 잃으면 화면에서 이전 대화를 바로 다시 선택할 수 없습니다.

AI core는 `/tokenize`로 시스템 지시·도구 정의·문답·도식 정보를 포함해 토큰 수를 셉니다.
32,768토큰 중 출력 4,096토큰과 여유 256토큰을 빼면 입력 예산은 28,416토큰입니다.
오래된 문답 쌍부터 제외하되 현재 질문·선택한 도식·현재 도구 실행 문맥은 유지합니다.
필수 내용만으로도 예산을 넘으면 오류를 반환합니다. 중단된 문답은 저장하되 후속 모델 문맥에서 제외합니다.

## 테스트와 검수

의존성을 설치한 뒤 저장소 루트에서 실행합니다. 아래 자동 테스트에는 실행 중인 GPU 모델이 필요하지 않습니다.

```bash
(cd ai-core && .venv/bin/python -m unittest discover -s tests -v)
(cd backend && ./gradlew --no-daemon test bootJar)
(cd frontend && npm test && npm run build)
git diff --check
```

UI 회귀 테스트는 별도로 실행합니다. API 응답을 격리해 메뉴, 대화·도식 복구, 확대·다운로드,
모바일 대화상자, 오류 후 재시도, 로드맵 선택·상태 복구와 개념별 대화 분리를 확인하며 GPU 모델은 필요하지 않습니다.

```bash
cd frontend
npx playwright install chromium  # 최초 1회 브라우저 설치
npm run test:ui
```

테스트는 전용 Vite 서버(127.0.0.1:5197)를 시작하고 종료합니다. 해당 포트를 비워 두세요.
이미 설치한 Chromium을 사용하려면 `BROWSER_EXECUTABLE_PATH=/절대/경로/chrome npm run test:ui`로 실행합니다.
기본 CI의 `Frontend` 검사는 기존 API 테스트와 빌드를 실행하며 브라우저 테스트는 별도 실행입니다.

[CI 설정](.github/workflows/ci.yml)은 main 대상 PR과 main push에서
`AI core`, `Backend`, `Frontend` 검사를 실행합니다. [GitHub Actions 결과](https://github.com/noveeda/cs-learning-agent/actions)를 확인할 수 있습니다.
CI는 GPU 모델을 다운로드하거나 실행하지 않으며 답변의 CS 정확성까지 보장하지 않습니다.

실제 모델을 켠 상태에서는 다음을 직접 검수합니다.

1. 질문 후 완성된 답변을 기다리는 동안 텍스트가 실시간 표시되는지 확인합니다.
2. 도식을 요청하고 후속 질문으로 연결 방향을 바꿔 봅니다.
3. 새로고침 후 대화와 도식이 복구되는지 확인합니다.
4. 새 학습을 시작하고 이전 대화가 섞이지 않는지 확인합니다.
5. 답변과 도식이 CS 개념을 정확히 설명하는지 별도로 검토합니다.

## 제약 및 관련 문서

- 현재는 인증 없는 로컬 개발 환경입니다. loopback 바인딩과 SSH 터널을 사용하며 공개 서비스용 인증·권한 제어는 구현하지 않았습니다.
- 대화 저장은 단일 백엔드 프로세스용 로컬 JSON 방식입니다. AI core는 프로세스당 한 요청을 처리합니다.
- 도식은 구조화된 노드·간선을 SVG로 그립니다. 간단한 격자 배치이며 복잡한 간선 교차나 설명의 의미적 정확성을 보장하지 않습니다.
- 브라우저는 SVG를 이미지로 표시합니다. 한글 글꼴은 필요한 글자만 SVG에 포함하며 [폰트 라이선스](ai-core/serving/assets/NotoSansKR-OFL.txt)를 동봉합니다.
- 현재 UI는 디자인 시안에 맞춰 공통 레이아웃·개념 학습 화면과 기본 로드맵을 적용한 단계입니다. 미구현 메뉴는 준비 중으로 표시합니다. 모바일에서는 메뉴를 접고 도식을 별도 대화상자로 표시하며, 통신 코드와 스트리밍·복구 동작은 유지 대상으로 검수합니다.
- 모델 실행 환경의 의존성 잠금 파일과 자동 배포 구성은 아직 없습니다. 위 모델 실행 예시는 새 GPU 환경에서 재검증이 필요합니다.
