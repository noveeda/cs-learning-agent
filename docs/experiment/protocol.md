# 비교 실험 진행 절차서 (진행자용)

- 현재 자료: `materials.json` version 2, 5과목 13개 후보 개념. 아래의 과목 제외·종이 시험·시간 배분은 초기 8개 개념 계획을 확장한 절차다.
- 대상 계획: [비교 실험 모드](../superpowers/plans/2026-10-26-mvp3-experiment-mode.md) 1절.
- 진행자는 참여자 옆에서 화면을 함께 보며 진행한다. 참여자가 묻지 않으면 도구 사용법 외에는 개입하지 않는다.

## 1. 하루 전

- [ ] 참여자별 코드와 일정을 정한다. 코드는 S1부터 참여 순서대로 준다(최대 S98). 코드 번호가 조건 배정을 정하므로 번호를 건너뛰지 않는다. S99는 리허설용으로 남겨 둔다.
- [ ] 참여자가 수강하지 않은 과목과 서술 답 수집에 이미 쓴 개념을 확인해 둔다. 시작 화면의 "제외할 개념"에서 해당 개념을 모두 선택한다. 과목 수강 여부를 별도 개인정보 항목으로 추가 수집하지 않고, 선택한 제외 목록으로 후보를 관리한다.
- [ ] 아래 과목별 후보 목록으로 제외할 개념을 확인한다. 미수강 과목의 점수만 낮아 학습 개념 두 개가 정해지거나 사전 시험이 불필요하게 길어지는 것을 막기 위한 절차다. 수강 중이어도 아직 배우지 않은 개념은 참여자에게 확인해 제외한다. 제외 뒤 후보가 2개 미만이면 세션을 만들지 않고 일정을 다시 잡는다.

| 과목 | 실험 후보 개념(개념 이름 · 체크박스에 보이는 ID) | 미수강 시 제외 |
| --- | --- | --- |
| 자료구조 | 해시 테이블 `hash-table`, 이진 탐색 트리 `bst`, 힙 `heap`, 퀵 정렬 `quick-sort`, 병합 정렬 `merge-sort`, 너비 우선 탐색 `bfs`, 위상 정렬 `topological-sort`, 동적 계획법 `dynamic-programming` | 해당 개념 전체. 자료구조 미수강자는 초기 참가자 기준에 따라 참여 대상에서 제외 |
| 운영체제 | SJF 스케줄링 `sjf`, 우선순위 스케줄링 `priority-scheduling` | 2개 모두 |
| 데이터베이스 | B-트리 인덱스 `btree-index` | 1개 |
| 네트워크 | 라우팅과 패킷 전달 `routing` | 1개 |
| 컴퓨터구조 | 캐시와 지역성 `cache-locality` | 1개 |

- [ ] 종이 선수 개념 확인 시험지와 답안 입력용 CSV를 준비한다. 정답 키는 참여자에게 보여 주지 않는다.
  - Git 밖 위치: `/home/infoserver/cs-eval-data/experiment/prereq-sheet/`.
  - 인쇄 파일: `선수개념확인_시험지.pdf`(A4). `sheet.html`도 같은 내용을 오프라인으로 연다.
  - 재생성: `python /home/infoserver/cs-eval-data/experiment/prereq-sheet/make_sheet.py --repo /home/infoserver/cs-learning-agent`(자료 PR 병합 뒤). 병합 전에는 `--repo /home/infoserver/cs-mvp4/exp-materials`로 검수한다. 기존 산출물은 `old/` 아래 시각별 폴더에 보관된다.
  - 전체 13개 후보의 선수 개념을 깊이 3까지 모아 중복 제거한 **32문항**이다(자료구조 24, 운영체제 4, 데이터베이스 1, 네트워크 2, 컴퓨터구조 1). 과목별로 묶고, 시스템 진단이 고르는 첫 문항 `d1` 대신 각 선수 개념의 두 번째 진단 문항 `d2`를 쓴다.
  - 미수강 과목의 종이 문항은 "미수강"이라고 쓰고 건너뛰게 한다. 배웠으나 모르겠는 문항은 빈칸 또는 "모름"으로 둔다. 두 상태를 오답 하나로 합치지 않는다.
- [ ] 동의서([consent.md](consent.md))를 인쇄하거나 화면으로 준비한다.

## 2. 시작 전 점검 (10분)

- [ ] 실험용 PC에서 서버로 SSH 터널을 연다. 실험 화면(5173)은 서버 안에서만 열려 있어 PC에서는 터널로만 접속한다.
  - Windows는 PowerShell, Mac은 터미널에서 실행한다(별도 설치 없음).
    ```bash
    ssh -p 60005 -N -L 5173:127.0.0.1:5173 infoserver@<서버주소>
    ```
  - `<서버주소>`: 서버와 같은 내부망이면 `192.168.1.122`, 밖이면 평소 접속하는 외부 주소.
  - 비밀번호는 진행자가 직접 입력하고 PC에 저장하지 않는다. 입력 후 아무것도 출력되지 않고 멈춰 있으면 정상이며, 이 창은 실험이 끝날 때까지 최소화만 해 둔다.
  - 공유기·ufw에 새로 열 포트는 없다. SSH 포트(60005)로 접속만 되면 된다.
- [ ] 서비스 상태: 같은 PC 브라우저에서 `http://localhost:5173/#/experiment`가 열린다. 서버에서는 `curl -s http://127.0.0.1:8001/health`가 ok인지 본다.
- [ ] 운영 모델(8000)에 다른 대량 측정이 돌고 있지 않은지 코디네이터에게 확인한다. 실험 중에는 대량 측정을 멈춘다.
- [ ] 노트북 화면 폭 1280px 이상, 브라우저 확대 100%.
- [ ] 다른 탭, 검색, 다른 AI 도구를 닫는다.
- [ ] 브라우저를 전체 화면(F11)으로 열고 주소창을 숨긴다. 주소에서 `#/experiment`를 지우면 일반 학습 앱이 열리므로, 참여자가 주소창을 건드리지 않게 한다.

## 3. 진행 (약 75~90분, 후보 8~13개 기준)

1. **안내(3분):** 동의서를 함께 읽고 동의를 받는다. 아래 문장만 말한다.
   > "두 가지 학습 도구를 비교하는 실험입니다. 성적과 관계없고, 틀려도 괜찮습니다. 막히면 화면에 있는 도구를 자유롭게 써 보세요."
   - 어느 도구가 "새로 만든 것"인지, 어느 쪽이 더 좋을 거라고 예상하는지는 말하지 않는다.
2. **종이 선수 개념 확인(약 15분):** 사이트의 문항이나 읽기 글을 열기 전에 시험지를 혼자 풀게 한다. 참여자 코드만 쓰고 이름은 받지 않는다. 미수강 과목은 "미수강", 배웠지만 모르는 문제는 빈칸 또는 "모름"으로 두며 찍도록 유도하지 않는다. 15분이 되면 풀던 곳에서 회수한다. 정답·점수·해설을 알려 주지 않고 다음 단계로 간다.
   - 종이 시험은 학생의 선수 지식과 실제 시스템 진단을 나중에 비교하기 위한 기준 자료다. 이 점수로 학습할 개념을 정하거나 시스템에 진단 결과를 미리 입력하지 않는다.
3. **시작 화면:** 참여자 코드, 학년, 자료구조 수강 여부를 입력하고 1절 표에 따라 미수강·미학습·기노출 개념을 "제외할 개념"에서 뺀다. 남은 후보 수 N과 아래의 사전 시험 시간을 참여자 코드와 함께 진행자 메모에 적는다. 같은 코드가 이미 있다는 경고가 나오면 새로 만들지 말고 "재개"를 고른다.
4. **사전 시험(후보 수에 따라 3~20분):** 후보마다 자동 채점 2문항이므로 총 2N문항이다. 기존 8개·16문항·12분과 같은 **개념당 1.5분(문항당 45초)**을 유지해, `1.5 × N`분을 올림한 시간으로 진행한다. 예: 후보 8개는 12분, 10개는 15분, 13개는 20분이다. 화면에는 사전 시험 시간 제한이 없으므로 진행자가 시계로 정한 시간을 재고, 지나면 풀지 못한 문항은 빈칸으로 제출하게 한다. 종이 시험과 사전 시험은 별도이며 시간을 합쳐 재지 않는다.
   - 13개를 모두 남기면 26문항이므로 일률적으로 12분 또는 15분을 적용하지 않는다. 같은 개념 수에는 같은 시간을 적용해 시간 부족에 따른 배정 차이를 줄인다.
5. **학습 1·2(각 최대 15분):** 화면에 나온 도구만 쓴다. 진행자는 시간만 본다. 도구 사용법을 물으면 버튼 위치만 알려 준다. 두 학습 단계의 15분은 화면이 서버 시각으로 막는다.
6. **사후 시험(약 10분)과 설문(약 5분)**
7. **마무리:** 참여에 감사하고, 원하면 정답 해설을 따로 보여 준다(종이 답안·사후 답·설문 기록이 모두 끝난 뒤).

- 시간 근거: 안내 3분 + 종이 15분 + 사전 12~20분 + 학습 최대 30분 + 사후 10분 + 설문 5분 = 75~83분이다. 단계 전환을 포함해 75~90분을 안내하며, 후보가 더 적거나 일찍 끝내면 줄어들 수 있다. 리허설에서 종이 32문항과 새 읽기 글의 소요 시간을 확인한다.

## 4. 문제가 생겼을 때

| 상황 | 대처 |
| --- | --- |
| 화면이 멈추거나 새로고침함 | 새로고침한다. 같은 단계와 남은 시간으로 돌아온다(서버 시각 기준). |
| 도구 응답이 30초 넘게 없음 | 기다린다. 오류 안내가 나오면 막힘 도구는 "다시 시도" 버튼을 누르고, 채팅 도구는 같은 질문을 다시 보낸다(채팅에는 다시 시도 버튼이 없다). 시간은 계속 흐르므로 진행자 메모에 기록한다. |
| 브라우저를 닫음 | 시작 화면에서 같은 코드로 "재개"를 고른다. |
| 화면이 연결 오류로 바뀜(터널 끊김) | 터널 창이 닫혔거나 SSH 연결이 끊긴 것이다. 같은 터널 명령을 다시 실행한 뒤 새로고침한다. 기록은 서버에 있어 같은 단계로 돌아온다. |
| 참여자가 중단을 원함 | 바로 멈춘다. 원하면 그 참여자의 기록을 지운다(코디네이터에게 코드를 알림). |

- 모든 예외 상황은 진행자 메모(참여자 코드, 시각, 내용)에 남긴다. 보고서에서 그 학생의 해당 개념을 따로 표시한다.

## 5. 끝난 뒤

- [ ] 종이 답안에 참여자 코드만 있는지 확인해 회수하고, `answer-key.json`으로 대조한다. `answers-template.csv`를 복사해 참여자별 한 행에 답을 입력한다. 모름·미응답은 빈칸, 미수강은 `NA`로 구분한다. 원본 템플릿에 실제 답을 덮어쓰지 않는다.
  - 작성한 CSV와 종이 답안은 Git 밖에서 진행자가 보관한다. `q1`~`q32`와 개념의 대응은 정답 키로 확인한다. 디지털 답안에 이름·연락처·학번을 덧붙이지 않는다.
  - 종이 답은 기존 `experiment_report.py`가 자동으로 합치지 않는다. 참여자 코드와 문항별 선수 개념을 기준으로 시스템 진단 기록과 별도 대조하고, 미수강·미응답 및 깊이·문항 수 제한으로 진단하지 않은 개념을 구분해 해석한다.

- [ ] 실험용 PC의 터널 창에서 `Ctrl + C`를 눌러 연결을 끊는다. 공용 PC라면 브라우저 방문 기록을 지운다(실험 진행 상태가 브라우저에도 저장된다).
- [ ] 그날 실험이 모두 끝나면 서버에서 Spring에 직접 요청해 기록을 내보낸다(Git 밖에 저장):
  `curl -s http://127.0.0.1:8080/api/experiments/export > ai-core/outputs/experiment/export-<날짜>.json`
  - 화면 주소(5173)를 거쳐 받지 않는다. 참여자 브라우저에서 기록이 열리지 않게 프록시 경유 요청은 막혀 있다.
- [ ] 사후 서술 답 채점 시트를 만들어 석사 과정생에게 전달한다:
  `ai-core/.venv/bin/python ai-core/eval/experiment_report.py grading-sheet --export <파일> --materials backend/src/main/resources/experiment/materials.json --grader G1 --out ai-core/outputs/experiment/grading-G1.csv`
  - 채점자에게는 참여자, 조건, 개념 순서를 알리지 않는다.
- [ ] 채점이 돌아오면 보고서를 만든다:
  `ai-core/.venv/bin/python ai-core/eval/experiment_report.py report --export <파일> --materials backend/src/main/resources/experiment/materials.json --grades <채점 시트 CSV들> --out ai-core/outputs/experiment/report.json`
- [ ] 보고서를 만든 뒤 원문을 모두 지우고 익명화한 수치(`report.json`)만 남긴다. 동의서 2절("분석이 끝나면 답과 대화 원문은 지우고")의 약속이다.
  1. 실험 기록: `backend/data/experiments/`의 세션 파일
  2. 학습 중 쓴 도구 기록: 실험 기록의 `stuck_session`·`chat_conversation` 사건이 가리키는 파일. 아래 명령으로 목록을 뽑아 확인한 뒤 지운다.
     ```bash
     jq -r '.. | objects | select(.type=="stuck_session" and .ref != null) | .ref' <export 파일> | sort -u | sed 's|^|backend/data/stuck-sessions/|; s|$|.json|'
     jq -r '.. | objects | select(.type=="chat_conversation" and .ref != null) | .ref' <export 파일> | sort -u | sed 's|^|backend/data/conversations/|; s|$|.json|'
     ```
     - `.ref != null`: 대상 ID가 없는 사건이 `null.json` 같은 잘못된 경로로 나오지 않게 거른다.
  3. 내보낸 파일(`export-<날짜>.json`)과 채점 시트 원문
  4. 회수한 종이 답안과 참여자별 선수 답안 CSV. 빈 시험지·정답 키·빈 템플릿은 참여 기록이 아니므로 재사용할 수 있다.
- [ ] 참여자 한 명의 기록만 지울 때(중단하며 삭제를 원하는 경우, 리허설 S99)는 다음 순서로 한다.
  1. 위 jq 명령 앞에 참여자 필터를 붙여 그 참여자의 도구 기록만 뽑는다. 예: S3
     ```bash
     jq -r '.sessions[] | select(.participant=="S3") | .. | objects | select(.type=="stuck_session" and .ref != null) | .ref' <export 파일>
     jq -r '.sessions[] | select(.participant=="S3") | .. | objects | select(.type=="chat_conversation" and .ref != null) | .ref' <export 파일>
     ```
  2. 그 참여자의 세션 파일(`backend/data/experiments/`)과 뽑은 도구 기록 파일을 지운다. 그 참여자의 종이 답안도 파기하고 선수 답안 CSV에서 해당 행을 제거한다. 다른 참여자의 파일과 답안은 건드리지 않는다.

## 6. 리허설

- 실제 실험 전에 사용자가 직접 참여자 역할로 한 번 진행한다(참여자 코드 `S99`). 종이 시험 15분, 후보 수에 따른 사전 시험 시간, 글 난이도, 화면 흐름을 확인하고 리허설이 끝나면 코디네이터가 S99 기록을 지운다(실험 API는 S1~S99만 받는다). 세션 파일뿐 아니라 리허설 중 쓴 막힘 세션·대화 기록도 5절의 "참여자 한 명의 기록만 지울 때" 방법으로 함께 지운다.
