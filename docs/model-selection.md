# 서빙 모델 선택 (2026-10-25)

- 막힘 학습 흐름의 LLM 역할 ①~④([프로젝트 방향](project-direction.md) Level 5)을 맡을 모델과 vLLM 설정을 시험으로 정한 기록이다.
- 결론: **gemma-4-26B-A4B-it AWQ 4bit 하나를 GPU 0번 한 장에서 8000번으로 서빙**하고, 모든 역할을 추론(thinking) 없이 실행한다. GPU 1번은 비워 두어 시뮬레이션 학습자·실험에 쓴다.
- 평가 자료·응답 원문·로그는 Git 밖 로컬 `codex/model-evaluation/roles/`에 있다. CS-300은 이번 평가에 쓰지 않았다(평가 전용 세트 유지).

- ① 지도 밖 발췌 10개는 EXAONE(9/10)을 빼고 모두 맞혔다. Qwen3-8B의 오답 4개는 지도 안 개념끼리의 혼동이었다.
- ③ kappa는 루브릭 항목 171개 기준이다. 거짓 통과는 기준상 미통과 답안 42개 중 모델이 모든 항목을 충족으로 판정한 수다. 모든 후보가 완전한 답안 15개는 모두 통과시켰다.
- ②④ 점수는 응답을 섞고 모델 이름을 가린 검토 결과다. "심각한 사실 오류"는 학습자에게 틀린 내용을 가르치는 오류다. 예: 로그 증가를 배수로 설명(log₂n이 "20배" 증가), 원형 큐가 원소를 앞으로 옮긴다는 설명, 파이썬 정수는 값을 직접 담는다는 설명.
- 한자 섞임은 "利用了", "操作中"처럼 한국어 설명 중간에 중국어가 섞인 응답 수다. Qwen 계열(Qwen3-8B 1건 포함)에서만 나타났다. 권장값 `presence_penalty=1.5`를 0으로 바꾸면 줄었지만(Qwen3.6-27B 3→1, Qwen3.5-9B 3→0) 다른 모델에서 없어진다는 보장은 없다.
- ④에서 여러 모델이 같은 사례(작은 n에서 n² 알고리즘이 빠를 수 있는 이유)를 틀린 이유로 요약했다. gemma 두 모델은 "n이 작으면 n²이 n log n보다 작다"고 썼다(실제 원인은 상수 계수). 복귀 요약에는 새 설명을 넣지 말라는 지시를 AI core 프롬프트에서 강화한다.

- 도식은 운영 채팅 코드(`run_agent`, 온도 0.2·추론 끔)로 요청 8개를 보낸 결과다. "첫 시도"는 도구 오류 없이 한 번에 SVG를 만든 수다. 도식이 필요 없는 질문 4개에서 도구를 부른 경우는 Qwen3.5-9B의 1건뿐이었다.
- **Gemma 4의 채팅 템플릿은 도구 스키마의 `$defs`·`$ref`와 `pattern`·`maximum` 같은 제약을 렌더링하지 않는다.** 현재 `create_diagram` 스키마(Pydantic 기본 `$defs` 구조)를 그대로 보내면 모델이 노드의 `column`·`row` 필드를 볼 수 없어 0/8이 된다. `$ref`를 펼치고 제약을 `description` 문장으로 덧붙이면 8/8이 된다(7절 참고).
- 지연은 `--max-num-seqs 1`에서 요청을 하나씩 보낸 중앙값이다. 생성 속도는 ② 설명의 출력 토큰 합을 시간 합으로 나눈 값이다.
- 긴 문맥 회상의 "부분"은 정답(0x1014)과 복습 주제는 맞혔지만 학습자가 처음 쓴 오답(0x1005)을 말하지 않은 경우다.
- ③ 지연은 측정 서버 설정에 따라 다르다. JSON 공백 금지 옵션(3-3)을 켠 서버 값은 gemma-4-26B-A4B(최종 구성), gemma-4-31B, Qwen3.6-35B-A3B, EXAONE-4.0-32B다. Qwen3-8B, Qwen3.5-9B, Qwen3.5-27B, Qwen3.6-27B는 옵션 없이 쟀다.
- 38K 토큰 대화의 첫 요청(캐시 없음)은 gemma-4-26B-A4B에서 10.8초가 걸렸다. vLLM 접두사 캐시가 켜져 있어 같은 대화의 다음 턴은 새로 추가된 부분만 계산한다.

### 3-3. 구조화 출력 잘림

- gemma-4-31B 채점 1건에서 학습자 답안의 따옴표(`d2["k"]`)를 evidence 문자열에 그대로 옮기다 문자열이 닫혔고, 이후 JSON 문법이 허용하는 공백만 1,024토큰까지 생성했다.
- 서버 옵션 `--structured-outputs-config '{"backend":"xgrammar","disable_any_whitespace":true}'`로 JSON 사이 공백을 금지하자 같은 사례가 정상 종료됐고, ③ 지연도 줄었다(gemma-4-31B 1.68 → 0.92초, gemma-4-26B-A4B 0.65 → 0.47초). 요청별 설정으로는 적용되지 않아 서버 옵션으로 둔다.

## 4. 결정과 근거

**서빙: gemma-4-26B-A4B-it AWQ 하나를 GPU 0번 한 장에서 8000번으로 서빙한다. 역할 ①~④와 기존 채팅 모두 이 모델을 쓰고 추론은 끈다.**

1. 역할 품질이 최상위권이다. ①은 56/56, ③은 거짓 통과 0/42에 kappa 0.92로 27B·31B와 같은 수준이다. ② 눈가림 검토에서 종합 점수가 가장 높고(4.27) 심각한 사실 오류와 한자 섞임이 없었다.
2. 장기 학습 보조에 필요한 조건을 GPU 한 장으로 만족한다.
   - 슬라이딩 윈도 주의 구조라 KV 캐시가 작다. GPU 한 장(`gpu-memory-utilization 0.9`)에 문맥 65,536토큰을 두고도 KV 여유가 118K 토큰이다.
   - 9.7K·19K·38K 토큰 대화 끝에서 초반 실수와 중간 복습 약속을 모두 회상했다. 8턴 대화에서 학습자가 정한 규칙을 끝까지 지켰다.
   - 활성 파라미터 4B인 MoE라 같은 GPU 한 장에서 생성 속도가 dense 27B의 약 3배다(134 대 43 tok/s). ①③은 1초 이내, ② 설명은 약 3초다.
3. **GPU 1번이 비어 있다.** Level 5의 시뮬레이션 학습자는 서빙과 다른 모델이어야 한다. GPU 1번에 Qwen3.6-27B(16K 문맥, 1장 측정 완료)나 Qwen3.5-9B를 올리면 계열이 다른 모델로 가상 학습자를 돌릴 수 있다.
4. 라이선스가 Apache-2.0이다.

추론을 끄는 이유:

- 선택 모델은 추론 없이 ①③ 천장에 도달했다. 작은 모델에서 추론은 채점 품질을 올렸지만 요청당 지연을 4~90배 늘렸다.
- 막힘 흐름은 한 세션에 LLM 호출이 여러 번 이어지므로 응답 지연이 학습 흐름을 직접 끊는다.

채택하지 않은 후보:

- gemma-4-31B는 도식 첫 시도·수정과 ④ 요약이 더 나았지만 GPU 2장을 모두 써야 하고 생성 속도가 절반 이하이며, ①③은 같은 수준이고 ② 설명 점수는 더 낮았다(3.91 대 4.27). 시뮬레이션 학습자 실험을 하지 않는 기간에 도식 품질이 더 중요해지면 대안으로 쓸 수 있다.
- Qwen3.5-27B(기존 운영)는 품질이 좋지만 GPU 2장이 필요하고 생성 속도가 절반 이하다. 1장이면 문맥이 16K로 줄어 긴 학습 대화를 담기 어렵다.
- Qwen3.6-27B는 ③이 가장 좋았지만 ② 설명에 심각한 사실 오류 3건과 한자 섞임 3건이 있었다.
- Qwen3-8B·Qwen3.5-9B는 ③ 거짓 통과와 ② 사실 오류가 많고, Qwen 계열은 한국어 설명에 한자가 섞였다.
- Qwen3.6-35B-A3B는 빠르지만 GPU 2장이 필요하고 거짓 통과 3/42, 8턴 규칙 이탈이 있었다.
- EXAONE-4.0-32B는 ③ kappa가 0.66으로 가장 낮고 비상업 라이선스다.

알려진 약점과 대응:

- **도식 도구:** Gemma 4 템플릿 때문에 현재 스키마로는 도식 호출이 실패한다. AI core가 도구 스키마를 펼쳐 보내야 한다(7절). 펼친 뒤에도 첫 시도 성공 5/8, 5개 이상 노드의 활성 도식 수정은 실패해 Qwen 27B보다 약하다. 막힘 흐름의 ② `explain`은 텍스트만 반환하므로 MVP 흐름에는 영향이 없고 자유 채팅의 도식에만 해당한다.
- **④ 요약 중 새 설명:** 복귀 요약이 개념을 새로 설명하다 틀린 사례가 있었다. 요약 프롬프트에서 새 설명을 금지하고 결과 목록만 연결하게 한다.

## 5. 한계

- ③ 기준 라벨과 답안은 평가 작성자(Claude)가 만든 것이다. **사람 채점자 라벨이 아니며** 채점자 간 일치도도 재지 않았다. 판정이 갈릴 수 있는 답안 8개는 따로 표시해 제외한 값도 계산했다. Level 5의 M3 목표(kappa 0.6 이상, 거짓 통과 10% 이하)는 사람 채점 세트로 다시 확인해야 한다.
- ① 정답 개념도 평가 작성자가 붙였다. 상위 후보가 모두 56/56이라 이 세트로는 상위 모델을 구분하지 못한다.
- ②④ 품질은 Claude 검토자의 눈가림 판정이다. 사람 검토가 아니며 문항 수가 적다(설명 11, 요약 6).
- 모든 수치는 1회 실행이다. ①③은 온도 0이라 같은 서버에서 재현되지만, 다른 vLLM 버전·GPU에서는 달라질 수 있다.
- Qwen3.5-27B·Qwen3.6-27B의 ② 설명은 GPU 1장과 2장에서 한 번씩 실행했다. 3-1 표는 1장 실행 값이다. 2장 실행의 한자 섞임은 두 모델 모두 1/11이었다(1장: 0/11, 3/11).
- 평가 프롬프트는 AI core가 실제로 쓸 프롬프트와 다를 수 있다. AI core가 역할을 연결한 뒤 같은 자료로 다시 확인한다.
- 긴 문맥 시험은 개념 지도 문장을 이어 붙인 합성 대화다. 실제 학습 대화의 다양성을 대표하지 않는다.

## 6. 실행 명령

운영 8000번(2026-10-26 재시작 기준):

```bash
CUDA_VISIBLE_DEVICES=0 "$HOME/.venvs/cs-vllm/bin/python" -m vllm.entrypoints.openai.api_server \
  --model "$HOME/.cache/huggingface/hub/models--cyankiwi--gemma-4-26B-A4B-it-AWQ-4bit/snapshots/0ef577a5710035bd2d3a3f27e4f5cb2e86a9a9ba" \
  --served-model-name gemma-4-26b-a4b-it-awq \
  --host 127.0.0.1 --port 8000 \
  --max-model-len 65536 \
  --max-num-seqs 1 \
  --gpu-memory-utilization 0.9 \
  --enable-auto-tool-choice --tool-call-parser gemma4 \
  --reasoning-parser gemma4 \
  --limit-mm-per-prompt '{"image":0,"audio":0,"video":0}' \
  --structured-outputs-config '{"backend":"xgrammar","disable_any_whitespace":true}'
```

| 인자 | 이유 |
| --- | --- |
| `CUDA_VISIBLE_DEVICES=0`, TP 없음 | GPU 1번을 시뮬레이션 학습자·실험용으로 비워 둔다. GPU 0번 사용량은 약 21.9GB다. |
| `--served-model-name gemma-4-26b-a4b-it-awq` | AI core는 `VLLM_MODEL`이 없으면 `/v1/models`의 첫 모델을 쓴다. 이 서버에는 모델이 하나뿐이다. |
| `--max-model-len 65536` | 긴 학습 대화를 담는다. KV 여유는 118,639토큰이다. AI core는 이 값을 문맥 예산으로 쓰므로 오래된 대화가 덜 잘린다. |
| `--max-num-seqs 1` | 기존 운영과 같이 요청을 하나씩 처리한다. AI core도 모델 잠금으로 한 번에 하나만 보낸다. |
| `--tool-call-parser gemma4`, `--reasoning-parser gemma4` | Gemma 4 도구 호출 형식 해석. 추론을 켜는 요청이 생기면 추론 내용을 `reasoning` 필드로 분리한다. 추론을 끈 요청의 출력에는 영향이 없다(시험 응답에 추론 누출 0건). |
| `--limit-mm-per-prompt` 0 | 이미지·오디오 입력을 쓰지 않으므로 멀티모달 메모리 예약을 줄인다. |
| `--structured-outputs-config ... disable_any_whitespace` | JSON schema 출력에서 공백 반복으로 출력 상한까지 가는 실패를 막는다(3-3). |

- 시험 명령과 서버 로그는 로컬 `codex/model-evaluation/roles/logs/`에 있다.
- 되돌리기: 이전 Qwen3.5-27B 2장 구성 명령은 로컬 `roles/baseline-8000-command.txt`에 원문으로 남겼다. 같은 GPU에서 다시 띄울 때 오래된 torch.compile 캐시로 시작이 실패하면 `VLLM_DISABLE_COMPILE_CACHE=1`을 붙인다(이번 시험에서 발생).

## 7. AI core가 적용할 역할별 설정

- 공통: `POST http://127.0.0.1:8000/v1/chat/completions`, 모델 `gemma-4-26b-a4b-it-awq`(또는 `/v1/models` 첫 id), 모든 요청에 `chat_template_kwargs: {"enable_thinking": false}`.
- 지연은 `--max-num-seqs 1`에서 잰 중앙값(최댓값)이다. 타임아웃은 측정값의 약 10배 이상으로 잡고, Spring → AI core 320초 안에 한 단계가 끝나게 한다.

| 역할 | 출력 형식 | 샘플링 | 추론 | max_tokens | 권장 타임아웃 | 측정 지연 |
| --- | --- | --- | --- | ---: | ---: | --- |
| ① 개념 특정 `identify` | `response_format` json_schema `{"concept": enum[개념 ID 36개 + "none"]}`, `"none"` → 지도 밖 | `temperature=0` | 끔 | 64 | 30초 | 0.15초(1.5) |
| ② 보충 설명 `explain` | 텍스트(마크다운 제목 없음, 300~600자) | `temperature=0.7, top_p=0.95, top_k=64`(아래 주의 참고) | 끔 | 1536 | 60초 | 2.8초(3.1) |
| ③ 서술 채점 `grade_explanation` | json_schema `{"criteria": [{"evidence": string ≤200, "met": bool}]}`, 배열 길이 = 루브릭 수(min/maxItems) | `temperature=0` | 끔 | 1024 | 30초 | 0.47초(2.8) |
| ④ 복귀 요약 `summarize` | 텍스트 2~4문장, 300자 이내 | `temperature=1.0, top_p=0.95, top_k=64` | 끔 | 512 | 30초 | 0.9초(1.0) |
| 기존 채팅·도식 `run_agent` | 스트리밍 텍스트 + `create_diagram` 도구 | 기존 `temperature=0.2` 유지 | 끔 | 4096(기존) | 120초(기존) | 첫 텍스트 0.2초, 도식 요청 약 20초 |

AI core 적용 시 주의:

- **도구 스키마 펼치기(필수):** `create_diagram`의 `parameters`에서 `$ref`를 `$defs` 내용으로 바꾸고 `$defs`를 지운다. `pattern`·`minimum`·`maximum`·`minLength`·`maxLength`·`minItems`·`maxItems`는 같은 필드의 `description`에 문장으로 덧붙인다(예: `"최솟값 0, 최댓값 3"`). 그래야 Gemma 4 템플릿이 노드 필드와 격자 범위를 모델에 보여 준다. `/tokenize`에 넘기는 도구 정의도 같은 것을 쓴다. 이 변경 전까지 운영 채팅의 도식 요청은 도구 검증 실패 후 텍스트 답변으로 끝난다(2026-10-26 8001에서 확인).
- ①③에서 `finish_reason == "length"`나 JSON 해석 실패는 판정 실패로 처리한다. 통과·충족으로 취급하지 않고 503(재시도 가능)으로 돌려준다.
- ③은 evidence를 먼저, met를 뒤에 두는 순서로 시험했다. 애매하면 미충족으로 판정하라는 지시와 답안 안의 지시문을 무시하라는 지시를 넣었다. 채점 지시를 삽입한 답안도 통과시키지 않았다.
- ①은 발췌를 `<<<`·`>>>`로 감싸 데이터로 전달하고, 선수 개념이 아니라 발췌의 주제 개념을 고르라고 지시했다.
- ④ 프롬프트에는 결과 목록에 있는 개념만 연결하고 새 설명을 하지 말라는 지시를 둔다(3-1의 오류 사례).
- ② explain의 temperature는 1.0에서 0.7로 낮췄다(PR #38 검수 후 조정).
  - 이유: 실제 8000번에서 반복 생성하자 명백한 사실 오류가 나왔다. 대부분 재보충 차수에서 모델이 즉석에서 만든 수치 예시와 정의 반전이었다(검수 4/66, 3차 3/22).
  - 해결: AI core 프롬프트를 보강하고(개념 지도 설명·학습 목표를 근거로 함, 정의는 설명 문장 그대로, 수치 예시 제한, 2·3차 방식 문구 교체) 온도를 함께 낮췄다.
  - 결과: 같은 프로토콜 99건에서 2/99였다(1차 0/33, 2차 2/33, 3차 0/33). 프롬프트만 바꾸고 1.0을 유지한 실행은 5/99였다. 온도만 낮췄을 때의 효과는 따로 재지 않았다.
  - 측정 자료: 로컬 `codex/model-evaluation/roles/explain-recheck/`.
- 평가에 쓴 프롬프트 원문은 로컬 `codex/model-evaluation/roles/harness.py`에 있다.
