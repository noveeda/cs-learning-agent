# 하네스·RAG 설계: 작은 모델로도 근거 있는 설명 (2026-10-28)

- 2026-10-28 사용자와 논의해 정한 **하네스와 RAG 설계**, 그리고 작은 gemma 모델 전환 여부를 정하는 **측정 계획**이다.
- 상위 문서는 [완성본 정의와 MVP 단계](2026-10-26-completion-roadmap-design.md)다. 이 문서와 어긋나는 부분은 이 문서가 우선한다.
- 표기
  - **(결정)**: 사용자가 정한 것
  - **(제안 채택)**: Claude가 제안하고 사용자가 승인한 것
  - **(Claude 판단)**: 아직 묻지 않아 Claude가 정한 것. 사용자가 바꿀 수 있다.

## 1. 의도

- 이 도구는 **CS 공부가 어려워 도움을 받으려는 전공생 개인**을 위한 것이다 **(결정)**.
- 사용자 문제의식: "모델이 스스로 생성한 답은 근거가 없다. 모델이 작을수록 더 그렇다." 교수님 질문 "이 설명에 환각이 없다고 말할 수 있나?"에도 답해야 한다.
- 방향: 작은 모델로도 지금(gemma-4-26B-A4B)과 비슷한 품질을 내면 **일반 PC(GPU 8GB, RAM 16GB)에서 도는 오픈소스 로컬 에이전트형 CS 학습 도구**로 전환한다 **(결정)**.
  - 비슷한 품질을 못 내면 지금처럼 서버형으로 남고, 로컬판은 측정값과 함께 "발전 가능성"으로 둔다.
- 핵심 원칙: **모델 출력은 믿지 않는 제안으로 취급하고, 코드가 검증한 것만 학생에게 보여 준다** **(제안 채택)**.
  - 흐름은 코드가 쥐고, 모델에는 작고 검사 가능한 일만 맡긴다.
  - 이미 이 방식으로 동작하는 진단 엔진, 문항 은행, 애니메이션 시뮬레이터의 원칙을 설명·채점까지 넓힌다.

## 2. 목표·비목표·실패 조건

**목표**
- 학습하기 채팅과 [막혔어요] 보충 설명의 문장마다 **공개 교재 근거**를 붙이고, 근거와 맞는지 검사한 문장만 그대로 보여 준다.
- 서술 채점에서 학생이 쓰지 않은 내용으로 통과시키는 일(거짓 통과)을 코드로 막는다.
- 하네스를 완성한 뒤 gemma 4 작은 모델(E4B, 12B, E2B)과 26B를 같은 하네스·같은 측정 세트로 비교한다.

**비목표**
- 로그인. 로컬 단독 사용이면 필요 없어 보류한다 **(결정)**.
- 복습 탭, 학습하기 매번 새 화면, [이해가 안 돼요] 버튼 이름 변경. 별도 작업으로 한다 **(결정)**.
- 일반 PC용 설치 패키지 만들기. 측정 결과로 전환이 정해진 뒤의 일이다.
- 파인튜닝. 측정 결과를 보고 정한다 **(결정)**.
- 교수자 통계 화면 개선. 본질 밖이다 **(결정)**.

**실패 조건** (기술적으로 동작해도 실패로 본다)
- 근거 검사를 통과하지 못한 문장이 표시 없이 학생에게 나간다.
- 61개념 지도 밖 질문에 답을 지어낸다.
- 측정 숫자가 사람이 확인할 수 없는 데이터에 기대고 있다.
- 진행 중인 학생 실험의 조건이 실험 도중에 바뀐다.

## 3. 제약

- **지도 밖 질문은 차단한다** **(결정)**. "이 도구는 5과목 61개념만 다룹니다"라는 고정 문구와 로드맵 바로가기만 보여 준다.
- **근거 자료는 공개 라이선스 교재**로 한다 **(결정)**. 후보와 라이선스 확인 결과는 `~/cs-handoff/research/rag-open-textbooks-2026-10-28.md`에 있다.
  - OSTEP은 공개 라이선스가 없어 제외한다. Dive into Systems는 ND(번역 금지)라 제외한다.
  - 빈칸: 조인 알고리즘(공개 교재 없음), 2의 보수(확실한 교재 미확인).
- **평가 데이터 원칙: 사용자가 검수할 수 없는 데이터는 평가 근거로 쓰지 않는다** **(결정)**.
  - CS-300과 모델 선택 때 쓴 평가 세트(Claude가 만든 개념 특정 56문항, 서술 판정 171개)는 쓰지 않는다.
  - 측정 세트는 **만드는 방식에서 정답이 정해지는 데이터**와 **사용자가 표본을 직접 확인한 데이터**로만 꾸린다.
- **모델은 gemma 4 계열**로 한다 **(결정)**. Qwen 계열은 한국어 설명에 한자가 섞여 제외한다.
- **목표 PC 사양: GPU 8GB, RAM 16GB** **(결정)**. 26B는 이 사양에 들어가지 않아 비교 기준으로만 쓴다.
- **GPU 사정**: GPU 0번은 운영 중인 26B가 약 22GB를 쓴다. GPU 1번은 2026-10-28 현재 다른 사용자(`hyeonseop`)의 데모가 약 22GB를 쓰고 있다. 측정 일정은 GPU 1번 조율 결과에 따른다.
- 기존 운영 규칙을 따른다.
  - 포트는 20000 이상을 쓴다.
  - 학생 기록은 Git 밖에 둔다.
  - main에 직접 커밋하지 않는다.
  - PR은 변경 파일 4~5개를 기본 목표로 한다.

## 4. 접근 방식

| 안 | 내용 | 대가 |
|---|---|---|
| **A. ai-core에 직접 구현, 색인은 파일 (채택)** | 단계마다 함수 하나씩 둔다. 기존 패턴(JSON 스키마 강제, 응답 후 재검증, `StuckModelGateway`)을 확장한다. 문단·그림·임베딩은 SQLite 파일 하나에 둔다. 모델은 OpenAI 호환 주소로 연결한다. | 검색과 파이프라인을 직접 짜야 한다 |
| B. RAG 프레임워크(LlamaIndex, LangGraph 등) | 문단 자르기와 검색은 빨리 붙는다 | 핵심(문장별 근거 번호, 근거 구절 글자 대조, 틀린 문장만 수정)은 어차피 직접 짜야 한다. 의존성이 커져 일반 PC 설치가 무겁다. 단계 사이가 잘 안 보인다. |
| C. A와 같되 색인은 벡터 DB 서버 | 문단이 수십만 개로 늘어도 버틴다 | 지금 규모(수천 개)에는 과하다. 학생 PC에 DB 서버가 하나 더 필요하다. |

- 사용자는 **A안**을 골랐다 **(결정)**.
- 이유: 하네스의 핵심 관문은 우리 코드여야 하고, 로컬 배포가 가벼워야 하며, 같은 코드로 서버(vLLM)와 일반 PC(llama.cpp)를 설정만 바꿔 오갈 수 있어야 한다.

## 5. 하네스 흐름

모든 모델 호출은 JSON 스키마로 출력 형식을 강제하고, 받은 뒤 코드가 다시 검증한다. 다음 단계는 항상 코드가 정한다.

### 5-0. 흐름 상태 (코드가 보관)
- 대화마다 현재 개념, 검색된 문단, 직전 질문을 보관한다.

### 5-1. 범위 결정 **(제안 채택)**
- **입력:** 학생 질문, 직전 개념, 61개념 목록(제목, 한 줄 설명)
- **출력:** `{concepts: 61개 ID 중 1~2개 | ["none"], follow_up: bool}`
  - 2개는 "스택과 큐 차이" 같은 비교 질문용이다. 두 개념의 문단을 함께 검색한다 **(Claude 판단)**.
- **검증:** 코드가 ID를 다시 확인한다. `follow_up`이 참이면 직전 개념을 이어 쓴다.
- **실패 처리**
  - 형식 오류가 나면 1회 재시도한다.
  - 그래도 실패하면 후보 개념 3개를 버튼으로 보여 주고 학생이 고르게 한다.
  - 후보 3개는 검색 단계의 유사도로 코드가 고른다 **(Claude 판단)**.
- `"none"`이면 차단 문구를 보여 준다(3절).
- 발췌문용 기존 `identify()`를 바탕으로 한다.
- **질문 유형별 처리** **(Claude 판단)**
  - "더 쉽게", "다른 예시로" 같은 후속 요청: 직전 개념과 문단을 이어 쓰고, 직전 답에서 검사를 통과한 문장을 5-3 입력에 넣는다.
  - 계산·과정 추적("factorial(4) 단계"): 해당 개념에 애니메이션 장면이 있으면 시뮬레이터 결과로 답한다. 장면이 없으면 일반 설명 흐름을 탄다.
  - 특정 코드의 오류 찾기·작성 요청: 61개념 설명이 아니므로 `none`으로 차단한다(3절 지원 범위 결정과 같은 이유).

### 5-2. 문서 검색 (모델 생성 없음)
- **사전 작업:** 교재 문단과 그림 캡션에 개념 ID 꼬리표를 붙인다(6절).
- **처리:** 해당 개념 꼬리표가 붙은 문단만 후보로 두고, 질문과 의미가 가까운 상위 3개를 고른다. 그림도 같은 방식으로 최대 1개 고른다.
- **검증:** 유사도가 기준 미만이면 생성하지 않고 "교재에 근거가 없음"으로 끝낸다. 기준값은 측정으로 정한다.

### 5-3. 근거 기반 생성
- **입력:** 질문, 문단 [1]~[3](원문), 개념 제목
- **[막혔어요] 재보충** **(결정)**
  - 기존 시도별 설명 방식(`EXPLAIN_APPROACHES`)의 2차(작은 예시 따라가기)와 3차(비유·오해)는 교재에 없는 내용을 만들게 하므로 쓰지 않는다.
  - 2차 시도는 그 개념의 애니메이션으로 대신한다. 시뮬레이터가 계산한 단계 설명을 근거로 인정한다. 근거 번호 종류에 "애니메이션 단계"를 더한다.
  - 3차 시도는 같은 개념의 **다른 교재 문단**(앞 시도에서 쓰지 않은 상위 문단)으로 다시 설명한다.
  - 애니메이션 장면이 없는 개념은 2차도 다른 교재 문단으로 설명한다.
- **출력:** `{sentences: [{text: 한국어 한 문장, sources: [1~3 중 1개 이상]}]}`, 최대 8문장
- **코드 검증**
  - 모든 문장에 근거 번호가 있는지
  - 번호가 실제 검색된 문단인지
  - 문장 길이
  - **한자 섞임:** CJK 통합 한자 범위 검사
- **실패 처리:** 1회 재시도한다. 그래도 실패하면 교재 문단 원문과 "설명 생성 실패" 안내만 보여 준다.

### 5-4. 일치 검사 (문장 하나 ↔ 그 문장이 가리킨 문단)
- **입력:** 한국어 문장 1개와 가리킨 문단. 생성 단계의 다른 문장이나 이유는 보여 주지 않는다.
- **출력:** `{verdict: 맞음 | 틀림 | 일부만, evidence: 문단에서 그대로 복사한 구절}`
- **코드 검증:** `evidence`가 문단에 글자 그대로 있는지 확인한다. 없으면 판정을 무효로 하고 "틀림"으로 처리한다.
  - 공백·줄바꿈 정규화는 허용한다 **(Claude 판단)**.
- "일부만"은 "틀림"과 같이 처리한다 **(Claude 판단)**.
- **판정 모델은 생성 모델과 같은 모델**을 쓴다 **(Claude 판단)**. 8GB에 두 모델을 함께 올릴 여유가 없기 때문이다.
  - 같은 모델의 자기 검사는 약할 수 있으므로, 판정 정확도를 8-1의 망가뜨린 문장 세트로 먼저 잰다. 이 값이 하네스 보장의 근거다.
  - 측정 때는 26B를 판정기로 쓴 경우도 함께 재서 자기 검사로 잃는 정도를 보고한다.

### 5-5. 수정
- **입력:** 틀린 문장, 해당 문단, 판정
- **출력:** 대체 문장 1개와 근거 번호. 다시 5-4를 거친다.
- **상한:** 1회
- **실패 처리**
  - 수정에 실패한 문장은 **"확인 필요"** 표시를 붙여 보여 준다.
  - 틀린 문장이 절반을 넘으면 답변 전체를 버리고 문단 원문을 보여 준다.

### 5-6. 표시
- **검사를 통과한 문장부터 한 문장씩 보여 준다** **(결정)**. 그 전에는 진행 상태("근거 찾는 중 → 설명 쓰는 중 → 확인 중")를 보여 준다.
  - 문장 순서를 지키기 위해 앞 문장의 검사(와 수정)가 끝나야 다음 문장을 보여 준다.
- 문장 옆에 근거 번호를 붙인다. 번호를 누르면 교재 원문 문단(영어)이나 애니메이션 단계가 나온다.
- 답 아래에 출처를 적는다. 형식은 교재명, 저자, 장·절, 라이선스, "발췌"다.
  - 화면에 원문만 보여 주고 실행 중 번역은 하지 않는다 **(Claude 판단)**. 번역도 검증해야 할 생성이기 때문이다.
- "확인 필요" 문장은 눈에 띄게 구분한다.
- 교재 그림을 골랐으면 그림, 원문 캡션, 출처를 함께 보여 준다.

### 5-7. 기록·측정
- 단계별로 다음을 기록한다. 기록은 Git 밖 `ai-core/outputs/` 아래에만 둔다.
  - 고른 개념
  - 문단 ID와 유사도
  - 생성 문장
  - 판정과 근거 구절
  - 재시도 횟수
  - 단계별 소요 시간

### 5-8. 같은 하네스를 쓰는 곳
- **학습하기 채팅:** 5-1~5-6 전체
- **[막혔어요] 보충 설명:** 개념을 이미 알고 있으므로 5-2~5-6
- **서술 채점:** 기존 항목별 `evidence`에 "학생 답에 글자 그대로 있는지" 코드 확인을 더한다. 없으면 그 항목은 미충족으로 처리한다.
  - 대조 전에 공백과 문장부호를 지운다 **(Claude 판단)**. 오타 허용 같은 느슨한 일치는 하지 않는다. 대신 이 규칙 때문에 맞는 답을 떨어뜨리는 비율(거짓 불통과)을 Mohler 번역 세트로 잰다.
  - 석사생 채점 세트는 아직 없다(사람 작업 예정). 생기면 같은 측정에 더한다.
- **복귀 요약(S7 `summarize`):** 모델 생성 대신 코드가 결과로 문장을 조립한다 **(Claude 판단)**. 보충 결과(통과·미해결)만 전달하면 되는 일이기 때문이다.

  - Watt: EPUB. 사이트가 자동 요청을 막아 **사람이 브라우저로 한 번 내려받아** 서버에 둔다. 차단을 우회하지 않는다.
  - OpenStax, Wikibooks: HTML
- **문단 단위:** 교재의 절(section)을 기준으로 자른다. 긴 절은 문단 묶음으로 나누고, 크기는 구현에서 정한다.
- **개념 꼬리표: 절 단위 대응표로 붙인다** **(Claude 판단)**.
  - 표의 예: "Hailperin 3.3 → round-robin, scheduling-metrics"
  - 문단마다 붙이면 검수량이 수천 건이지만, 절 단위 표면 수백 줄이라 **사용자가 직접 검수할 수 있다**. 이 표가 근거 자료의 정답지다.
- **그림:** 캡션과 소속 절로 같은 꼬리표를 받는다.
  - 그림 파일은 PNG로 변환해 둔다.
  - 그림별 라이선스를 확인한다. Peterson & Davie의 일부 그림 파일 이름에 원 출판사 판 ISBN이 있고, OpenStax는 그림별 출처 표기가 있다.
  - 확인되지 않은 그림은 쓰지 않는다.
- **저장 위치:** 교재 문단, 그림, 색인은 Git 밖(`ai-core/data/rag/`, gitignore)에 둔다.
  - 저장소에는 **원본을 받아 색인을 다시 만드는 스크립트와 대응표만** 커밋한다 **(Claude 판단)**.
  - 이렇게 하면 SA·NC 라이선스 표기 의무를 저장소 전체로 퍼뜨리지 않는다.
- **임베딩 모델:** CPU에서 돌고 RAM 약 1GB 이하이며 라이선스가 허용적이어야 한다. 한국어 질문과 영어 문단을 이어야 하므로 다국어 모델이어야 한다. 구체 모델은 5-2 측정(정답 문단 회수율)으로 고른다.
- **빈칸 개념:** 근거 문단이 없는 개념은 5-2에서 "교재에 근거가 없음"으로 끝난다. 빈칸을 채울지는 측정 뒤에 정한다.

## 8. 측정 계획

### 8-1. 측정 세트 (만드는 방식에서 정답이 정해지는 것)

| 단계 | 세트 | 정답의 근거 |
|---|---|---|
| 5-1 범위 결정 | 개념마다 학생 말투 질문 + 지도 밖 질문 + 후속 질문 | "이 개념용으로 만든 질문"이라는 생성 규칙. 사용자가 개념당 표본 1~2개 확인 |
| 5-2 검색 | 교재 문단 하나를 보고 만든 질문 | 질문을 만든 그 문단이 정답 |
| 5-4 일치 검사 | 근거가 맞는 문장과, 그 문장을 일부러 망가뜨린 문장 | 망가뜨린 방식(숫자 바꾸기, 반대로 말하기, 없는 내용 덧붙이기)이 곧 정답 |
| 5-3·5-5 생성 전체 | 5-1 세트 질문을 하네스로 처리한 답 | 26B 판정기(5-4 세트로 정확도를 먼저 확인)로 채점 + 사용자 표본 확인 |
| 서술 채점 | 사람이 채점한 데이터만. Mohler 번역본, 석사생 채점 세트 | 사람 채점 |

- 질문과 문장을 만드는 모델은 gemma 26B다(Apache-2.0) **(Claude 판단)**. gpt-6-astra 출력은 나중에 학습 데이터로 쓸 수 있으므로 측정 세트 생성에 쓰지 않는다.
- 지금 실험 자료나 문항 은행과 문장이 겹치지 않게 한다.

### 8-2. 지표
- **단계별 정확도:** 범위 결정 정확도, 정답 문단 상위 3개 회수율, 일치 검사의 틀린 문장 검출률과 오경보율
- **노출 지표 (가장 중요):** 학생에게 표시 없이 나간 문장 중 근거와 맞지 않는 문장의 비율
- **"확인 필요" 비율, 근거 없음 비율, 한자 섞임 건수**
- **속도:** 단계별 시간, 답변 전체 시간의 중앙값과 90% 값. 3090에서 잰 값은 RTX 4060급보다 빠르므로 보정해서 보고한다.

### 8-3. 비교 대상
- 같은 하네스, 같은 세트로 비교한다.
  - gemma-4-26B-A4B: 기준
  - gemma-4-E4B: 1순위
  - gemma-4-12B
  - gemma-4-E2B: 예비
- E4B는 4비트와 8비트를 모두 잰다.
- 작은 모델은 llama.cpp로 GPU 메모리 8GB 이내에서 돌리고, 사용량을 기록한다.

### 8-4. 전환 판단 기준
- 품질 기준 **(제안 채택, 2026-10-28 설계 승인)**
  - 단계별 지표가 26B보다 5%p 이상 나쁘지 않을 것
  - 노출 지표가 2% 이하일 것
  - 한자 섞임 0건
- **시간 기준** **(결정)**: 첫 문장 표시까지 10초, 답변 전체 30초(허용 오차 ±5초, 35초까지 통과).
  - 90% 값으로 판단하고, 3090 측정값을 RTX 4060급으로 보정한 추정치를 함께 보고한다 **(Claude 판단)**.

## 9. 운영 반영과 실험 보호

- 새 하네스는 **설정 스위치 하나로 켜고 끈다**. 운영 기본값은 끔이다 **(Claude 판단)**.
  - 스위치 하나가 이 문서의 모든 동작 변경을 묶는다: 채팅 하네스, 자유 도식 제거, 보충 설명, 채점 글자 대조, 복귀 요약.
  - 끄면 지금과 똑같이 동작한다. 실험의 채팅 대조군과 사전 시험 채점도 그대로다.
  - 자유 도식 코드는 스위치를 운영에서 켜기로 확정한 뒤에 지운다.
  - 이유: 학생 실험이 [막혔어요] 보충 설명을 쓴다. 실험 도중 설명 방식이 바뀌면 참가자마다 조건이 달라진다.
  - 운영에서 켜는 시점은 사용자가 정한다.
- Spring은 지금 채팅 이벤트 중 `artifact`를 대화 기록에 저장해 새로고침 때 복원한다. 근거 번호, 출처, "확인 필요", 교재 그림이 담긴 새 답변 형식도 같은 방식으로 저장·복원해야 한다.
- 화면 변경
  - 근거 번호와 원문 보기
  - 출처
  - "확인 필요" 표시
  - 교재 그림
  - 차단 문구
  - 자유 도식 제거

## 10. 작업 순서 (제안)

1. 교재 원본 수집과 절 단위 대응표 초안을 만든다. 사용자가 대응표를 검수한다.
2. 문단·그림 색인과 5-2 검색을 만들고, 임베딩 모델을 고른다.
3. 하네스 5-1, 5-3~5-5와 기록(5-7)을 만든다.
4. [막혔어요] 보충 설명과 서술 채점에 적용한다.
5. 화면 표시와 Spring 저장을 만든다.
6. 측정 세트를 만들고, 사용자가 표본을 확인한다.
7. 26B와 작은 모델들을 측정하고 보고한다. 결과로 전환과 파인튜닝 여부를 정한다.
