# 12B 하네스 역할 미세조정 설계 (초안)

- 작성: 2026-10-29
- 상태: 사용자 승인(2026-10-29). 9장 결정 반영.
- 선행 문서: `docs/superpowers/specs/2026-10-28-harness-rag-design.md`(하네스·RAG 설계, 이하 "하네스 설계"), `docs/harness-measurement.md`(모델별 측정)
- 표기: **(결정)** 사용자가 정한 것, **(제안 채택)** 사용자가 승인한 제안, **(Claude 판단)** 사용자가 아직 확인하지 않은 Claude의 결정, **(측정 후 확정)** Task 11 결과로 정할 것

## 1. 왜 하는가

- 목표는 일반 PC(GPU 8GB, RAM 16GB)에서 도는 오픈소스 로컬 CS 학습 도구다. 그 바탕 모델은 gemma 4 12B다 **(결정, 2026-10-29)**.
  - E4B·E2B는 판정이 약해 뺐다 **(결정)**. E4B Q4는 틀린 문장 검출 38%, 노출 지표 7.3%였다.
- 하네스·RAG만 붙인 12B는 단계별 지표가 대부분 26B와 5%p 이내다. 노출 지표만 기준을 넘는다.
  - 노출 지표는 표시 없이 나간 문장 중 교재와 맞지 않는 문장의 비율이다. 기준은 2% 이하인데, 12B Q4 중간값이 5.9%(303/485문항)다.
  - 원인은 일치 판정 단계다. 틀린 문장의 약 30%를 놓친다. 특히 없는 내용을 덧붙인 문장에 약하다.
- 그래서 하네스가 12B에게 시키는 역할을 26B와 구성상 정답으로 가르쳐, 노출 지표를 기준 안으로 넣는다.

## 2. 목표·비목표·실패 조건

- **목표**
  - 미세조정한 12B가 하네스 설계 8-4 기준을 모두 통과한다. 특히 노출 지표 2% 이하, 일치 판정 검출률 26B −5%p 이내다.
  - 결과물은 llama.cpp에서 도는 GGUF 한 파일이다(4비트, GPU 8GB 이내). 사용자는 파일 하나만 받으면 된다.
- **비목표**
  - 모델이 CS 지식을 외우게 하는 것. 사실의 근거는 계속 교재 문단(RAG)이다.
  - 26B를 넘는 일반 성능. 판정은 구성상 정답 덕분에 26B를 넘을 수 있지만, 그것을 목표로 잡지 않는다.
  - 서술 채점 역할 학습. 12B가 이미 기준을 통과했고(거짓 통과 5.2% vs 26B 4.7%), 채점 측정 세트(Mohler)를 학습에 쓰면 측정이 오염된다.
- **실패 조건** (기술적으로는 돌아도 실패로 보는 것)
  - 측정 세트 문항·문단이 학습에 섞여 점수가 부풀려진 것
  - 학습한 개념에서만 좋아지고, 빼 둔 개념에서는 그대로이거나 나빠진 것
  - 범위 결정·채점처럼 이미 통과한 지표가 2%p 넘게 나빠진 것
  - 한자가 섞이기 시작한 것

## 3. 접근 방식

| 방식 | 내용 | 판단 |
|---|---|---|
| A. 전부 26B 따라 하기 | 모든 역할에서 26B 출력을 그대로 학습 | 26B의 실수까지 배운다. 덧붙인 문장을 26B도 51%만 잡는다. |
| **B. 섞기** | 판정·범위는 구성상 정답, 생성·수정은 검사를 통과한 26B 출력 | **채택 (결정, 2026-10-29)** |
| C. 판정만 | 일치 판정 역할만 학습 | 가장 빠르지만 생성이 처음부터 덜 틀리게 만드는 효과가 없다. |

- B를 고른 이유는 두 가지다.
  - 판정은 26B 판단이 아니라 "일부러 망가뜨린 문장은 틀림"이라는 구성으로 정답을 정하므로, 교사의 실수를 물려받지 않는다.
  - 생성은 구성으로 정답을 만들 수 없어 26B를 쓰되, 하네스 검사(문단 글자 대조 + 26B 판정)를 통과한 출력만 쓴다.

## 4. 학습할 역할과 데이터

- 모든 예시는 운영 하네스와 **같은 지시문(`stuck_llm.PROMPTS`)·같은 JSON 스키마·같은 입력 모양**으로 만든다. 학습한 형식과 실제 호출 형식이 어긋나지 않게 하기 위해서다 **(Claude 판단)**.
- 생성 모델은 gemma 26B(운영 8000번)만 쓴다 **(결정, 2026-10-28)**.

| 역할 | 정답 출처 | 목표 분량 (Claude 판단) |
|---|---|---|
| **judge (일치 판정)** — 주 대상 | 맞음: 26B 하네스가 verified로 낸 문장(문단 글자 대조 통과). 틀림: 그 문장을 망가뜨린 것. 숫자 바꾸기·반대로 말하기는 규칙으로, 덧붙이기·개념 바꾸기는 26B가 만든다. | 6,000쌍(맞음·틀림 반반, 덧붙이기 비중을 측정 세트보다 높게 40%) |
| **ground (근거 기반 생성)** | 26B 하네스 답 중 모든 문장이 verified이고, 26B 별도 판정도 통과한 답 | 3,000개 |
| **repair (틀린 문장 수정)** | 26B가 고친 문장 중 재판정이 supported인 것 | 1,000개 |
| **scope (범위 결정)** | 생성 규칙: "이 개념용으로 만든 질문", 지도 밖·후속 질문 포함 | 3,000개 (이미 통과한 역할이 나빠지지 않게 하는 유지용) |

- 질문은 측정 세트와 같은 생성기(`eval/harness_sets*.py`)로 새로 만든다. 이미 있는 측정 문항과 같은 문장은 버린다.
- 일치 판정의 "덧붙이기·개념 바꾸기" 품질은 사용자의 판정 표본 확인(http://localhost:20100/review/judge-sample.html)으로 검증받는 것과 같은 방식이다. 표본에서 문제가 나오면 그 방식을 고친 뒤 학습 데이터를 만든다.

## 5. 측정 오염 방지

- **문단은 공유, 질문만 분리** **(결정, 2026-10-29)**
  - 측정에 쓴 문단을 학습에서 엄격히 빼면 재료가 바닥난다(정답·판정 문단만 빼도 15개 개념이 3개 미만, 검색 문단까지 빼면 대부분 개념이 바닥).
  - 그래서 문단은 학습에도 쓰고, 측정 세트 질문과 같은 질문(공백·문장부호 제거 후 일치)만 버린다.
  - 학습한 개념의 점수는 문단을 미리 본 효과로 부풀 수 있다. 보고서에 학습 개념과 제외 개념을 나눠 적고, **합격 판정은 제외 개념 기준**으로 한다.
- **개념 통째 제외: 10개** **(결정, 2026-10-29)**
  - 과목마다 2개씩, 근거 문단이 3개 이상인 개념 중에서 seed를 고정해 고르고 목록을 문서에 남긴다.
  - 이 10개념은 학습 예시의 질문·근거 문단·교란 문장 어디에도 나오지 않는다.
- 학습 데이터 파일은 Git 밖(`ai-core/outputs/finetune/`)에 두고, 만든 조건(seed, 색인·대응표 커밋, 26B 리비전)을 `meta.json`에 남긴다.

## 6. 학습 방법

- **QLoRA** **(결정, 2026-10-29)**
  - 예비안: QLoRA 결과가 기준에 아슬아슬하게 못 미치면, 데이터 생성이 끝나 26B가 필요 없어진 뒤 GPU 두 장으로 16비트 LoRA를 한 번 더 학습해 비교한다(운영 26B를 내리는 것은 그때 사용자 허락).
  - 바탕 가중치를 4비트로 올리고 작은 어댑터만 학습한다. 3090 24GB 한 장(GPU 1번)으로 12B를 학습할 수 있다.
  - 환경: `~/.venvs/cs-train`(저장소 밖; torch 2.13 cu130, transformers 5.21, peft 0.21, trl 1.16, bitsandbytes 0.50) **(결정, 설치 완료)**
  - 시작 설정: LoRA r=16, alpha=32, 모든 선형층, 학습률 1e-4, 2에폭, 문맥 4096. 검증 손실로 조기 종료한다.
- **바탕 모델** **(측정 후 확정)**
  - Task 11에서 12B Q4_K_M이 이기면 `google/gemma-4-12B-it`(BF16)로 학습하고 Q4_K_M으로 만든다.
  - QAT가 이기면 `google/gemma-4-12B-it-qat-q4_0-unquantized`로 학습하고 Q4_0으로 만든다. 4비트 손실이 적다는 QAT의 장점을 유지하기 위해서다.
- **내보내기:** 어댑터를 병합 → `~/llama.cpp/convert_hf_to_gguf.py` → `llama-quantize`로 4비트 GGUF를 만든다. Mi:dm 변환에 쓴 같은 경로다.
- 학습은 사고(thinking) 모드를 끈 대화 형식으로 한다. 운영 하네스가 사고 모드를 끄기 때문이다.

## 7. 검증

- Task 11과 **같은 측정 도구(`eval/harness_measure.py`)·같은 세트·같은 설정**으로 다시 잰다.
- 통과 조건
  - 하네스 설계 8-4 전부: 단계별 26B −5%p 이내, 노출 지표 2% 이하, 한자 0건, 첫 문장 10초·전체 30초(4060 보정, ±5초)
  - 미세조정 전 12B보다 범위 결정·채점이 2%p 넘게 나빠지지 않을 것
  - 빼 둔 10개념에서 노출 지표·판정 검출률이 좋아질 것(나빠지면 실패). 이 판단이 합격 판정의 기준이다.
- **26B와 독립된 검사** **(결정, 2026-10-29)**
  - 26B는 교사라서, 12B가 26B 의견을 닮기만 해도 26B 검사 점수가 좋아진다(26B 자기 검사 노출 0.1%). 그래서 합격 조건에 아래 둘을 함께 넣는다.
  - 사용자 표본 50개: 미세조정 모델 답에서 고른 문장을 사용자가 교재 문단과 대조한다.
  - gpt-6-astra 검사: 노출 지표를 astra로도 잰다. 측정 검사에만 쓰고 학습 데이터에는 넣지 않는다(2026-10-28 원칙). 노출 지표는 26B·astra 둘 다 2% 이하여야 통과다.
  - 판정 검출률은 26B가 만든 교란(덧붙이기·개념 바꾸기)과 규칙 교란(숫자 바꾸기·반대로 말하기)을 따로 보고한다. 규칙 교란 점수는 교사의 문체와 무관하다.
- MTP 추측 디코딩: 보조 파일은 원래 12B에 맞춰 학습된 것이라, 미세조정 뒤에는 짐작 적중률이 떨어져 속도 이득이 줄 수 있다. 출력은 같다. 켠 조건과 끈 조건 시간을 둘 다 잰다.

- **바탕 모델 고르는 기준** **(Claude 판단)**: 노출 지표 → 일치 판정 검출률 → 단독 요청 GPU 메모리 8GB 이내 여부 → 시간 순으로 비교한다. 앞의 두 지표 차이가 1%p 이내면 메모리가 작은 쪽(QAT)을 고른다.
- **빼 둔 개념의 판단 방법** **(Claude 판단)**
  - 기존 측정 세트만으로는 빼 둔 개념의 답이 약 50개라 잡음이 크다. 그래서 빼 둔 개념마다 측정 질문을 30개씩 새로 만든다(측정 세트와 같은 생성기, 26B).
  - 판정 기준은 미세조정 전후 차이의 95% 부트스트랩 신뢰구간이다. 노출 지표와 판정 검출률의 개선 구간이 0을 넘으면 "좋아짐", 악화 구간이 0을 넘으면 "나빠짐"(실패)이다.

## 8. 순서

1. Task 11 끝 → 바탕 모델(Q4_K_M 원본 / QAT) 확정
2. 학습 데이터 생성기 (TDD; 분리 규칙·형식 일치 테스트) → 26B로 생성 (몇 시간)
3. QLoRA 학습 → GGUF 변환
4. 같은 측정 → 보고서 → 사용자에게 전환 결정 요청

### 9-1. 교재 라이선스

- 학습 데이터의 근거 문단은 공개 교재 8권에서 온다. 그중 일부는 "같은 조건으로 배포(SA)"나 "비상업(NC)" 조건이 붙어 있다.
  - CC BY: ods, Erickson, Peterson-Davie, Watt
  - CC BY-SA: Hailperin, Wikibooks
  - CC BY-NC-SA: OpenStax, UTA
- 이런 글로 학습한 모델 가중치가 교재의 "2차 저작물"인지는 법적으로 정해지지 않았다.
- 선택지
  - (가) 8권 전부 사용: 근거가 가장 넓다. 배포 모델에 SA·NC 해석 위험이 남는다.
  - (나) CC BY 4권만 학습에 사용: 배포 위험이 가장 작다. 검색(RAG)은 지금처럼 8권 그대로다. 학습 예시가 줄어들고 과목에 따라 치우칠 수 있다.
- **결정: (가) 8권 전부** **(2026-10-29)**
  - (나)는 CC BY 4권만으로는 59개 개념 중 21개가 학습 문단 0개라 쓸 수 없다(설계 검토에서 실측).
  - 배포 모델 설명(모델 카드)에 학습에 쓴 교재 8권과 각 라이선스를 밝히고, 비상업 오픈소스로 배포한다. 유료화를 하지 않으므로 NC 조건과 부딪히지 않는다.
  - SA 조건이 모델 가중치에 미치는지는 법적으로 정해지지 않은 위험으로 남는다.
