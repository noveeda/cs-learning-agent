# 12B 하네스 역할 미세조정 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> 이 저장소에서는 Orca 워커가 Task 단위로 실행한다(코디네이터 편). 워커는 `orca-superpowers` 워커 편을 따른다.

**Goal:** gemma 4 12B를 하네스 역할(judge·ground·repair·scope)로 QLoRA 미세조정해, 8GB GPU용 GGUF 한 파일로 하네스 설계 8-4 기준(특히 노출 지표 2% 이하)을 통과시킨다.

**Architecture:**
- 학습 데이터는 두 갈래로 만든다.
  - judge·scope는 구성상 정답이다.
  - ground·repair는 26B 하네스 실행을 녹화한 것 중 검사를 통과한 호출이다.
- 측정에 쓴 질문과 제외 개념 8개는 학습에서 뺀다.
- 학습은 저장소 밖 `~/.venvs/cs-train`에서 QLoRA로 한다. 결과는 llama.cpp로 GGUF를 만든다.
- 검증은 Task 11 측정 도구에 세 가지를 더해 다시 잰다.
  - 제외 개념 분리 보고
  - 신뢰구간
  - astra 독립 검사

**Tech Stack:**
- Python 3.12(ai-core venv)
- 학습 환경 `~/.venvs/cs-train`: torch 2.13 cu130, transformers 5.21, peft 0.21, trl 1.16, bitsandbytes 0.50
- llama.cpp `~/llama.cpp`(convert_hf_to_gguf.py, llama-quantize)
- vLLM 26B(8000)
- Codex CLI(gpt-6-astra)

**Spec:** `docs/superpowers/specs/2026-10-29-finetune-12b-design.md` (선행: `docs/superpowers/specs/2026-10-28-harness-rag-design.md`, `docs/harness-measurement.md`)

## Global Constraints

- 학습·측정 데이터 생성 모델은 gemma 26B(운영 8000번)뿐이다. gpt-6-astra는 측정 검사(노출 지표 독립 검사)에만 쓰고, 그 출력은 학습 데이터에 넣지 않는다.
- 학습 예시는 운영 하네스와 같은 지시문(`serving.stuck_llm.PROMPTS[role]`), 같은 user JSON(`json.dumps(payload, ensure_ascii=False)`), 같은 스키마를 쓴다. assistant 출력은 공백 없는 JSON 한 줄(`json.dumps(obj, ensure_ascii=False, separators=(',', ':'))`)이다.
- 학습 대상 역할은 judge·ground·repair·scope다. grade_explanation(서술 채점)은 학습하지 않는다.
- 목표 분량
  - judge 6,000행(맞음·틀림 반반, 틀림 중 addition 40%)
  - ground 3,000개
  - repair 1,000개
  - scope 3,000개
  - 각 역할의 5%를 seed 고정으로 검증용(valid)으로 뗀다.
- 제외 개념은 8개다(운영체제 0개, 나머지 4과목 2개씩). 근거 문단이 3개 이상인 개념 중 고르고, 제외 뒤 나머지 개념의 학습 절이 3개 이상 남을 때까지 seed를 0부터 올린다. 이 개념은 학습 예시의 질문·정답 개념·근거 문단·교란 문장 어디에도 나오지 않는다.
- 문단은 학습과 측정이 공유한다. 측정 세트 질문과 정규화(공백·문장부호 제거) 후 같은 질문만 버린다.
- 교재 8권을 모두 쓴다. 배포용 모델 설명에 교재와 라이선스를 밝힌다.
- 바탕 모델은 Task 11 결과로 정한다.
  - 고르는 순서: 노출 지표 → 판정 검출률 → 단독 요청 8GB 이내 → 시간. 앞의 두 지표 차이가 1%p 이내면 QAT다.
  - Q4_K_M이 이기면 `google/gemma-4-12B-it`으로 학습하고 Q4_K_M으로 만든다.
  - QAT가 이기면 `google/gemma-4-12B-it-qat-q4_0-unquantized`로 학습하고 Q4_0으로 만든다.
- 학습 데이터·어댑터·가중치·측정 원본은 Git 밖에 둔다. 제외 개념 목록(`ai-core/content/finetune/holdout.json`)만 커밋한다.
  - 학습 데이터·측정 원본: `ai-core/outputs/finetune/`
  - 어댑터·가중치: `~/.cache/cs-llm/finetune/`
- 운영 서비스(8000, 8001, 8080, 5173)는 멈추거나 재시작하지 않는다. 시험 서버는 20300~20399만 쓴다. 학습·변환은 GPU 1번(`CUDA_VISIBLE_DEVICES=1`)만 쓴다.
- 26B 데이터 생성은 동시 요청 8까지 허용한다(사용자 허락, 학생 실험 전).
- 사고(thinking) 모드는 생성·학습 모두 끈다.
- 학습 스크립트는 `~/.venvs/cs-train`으로 실행한다. ai-core 테스트와 CI는 trl·peft 없이 돌아야 하므로, 테스트 대상 모듈은 이 라이브러리를 최상위에서 import하지 않는다.

## Review Focus

1. 한 문단이 제외 개념과 학습 개념에 함께 대응될 때(절 대응표의 다개념 절)는 그 문단을 학습에서 뺀다. 그래야 제외 개념의 근거가 학습으로 새지 않는다 → Task 1 `test_passage_shared_with_holdout_is_excluded`
2. 측정 질문과 띄어쓰기·문장부호만 다른 질문은 측정 질문으로 보고 버린다 → Task 1 `test_normalized_duplicate_is_measured`
3. assistant 출력은 공백 없는 한 줄 JSON이고 한글이 이스케이프되지 않는다. 다르면 운영 xgrammar 문법과 어긋난다 → Task 2 `test_assistant_content_is_compact_json`
4. 26B 호출이 실패·재시도·잘림(finish_reason=length)이었던 녹화는 학습 행이 되지 않는다. 마지막 성공 응답만 쓴다 → Task 2 `test_failed_or_truncated_calls_are_not_recorded`
5. 한자가 섞인 출력이나 비교 질문의 한쪽이 제외 개념인 scope 행은 버린다 → Task 3 `test_drops_han_and_holdout_compare`
