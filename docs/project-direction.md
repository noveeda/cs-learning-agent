## Level 0. 궁극 목표

> **CS를 공부하다 막힌 학습자에게, 막힌 개념을 이해하는 데 부족한 선수 개념을 진단해 필요한 만큼만 보충하고, 이해를 확인한 뒤 원래 하던 학습으로 돌려보낸다.**

- 줄이려는 결과: 막힌 지점에서의 학습 포기, 불필요한 처음부터 다시 공부, 이해했다는 착각.

## Level 1. 사용자·문제·차별점

### 사용자

| 구분 | 대상 | 이유 |
| --- | --- | --- |
| 주 사용자 | 전공 과목을 공부하는 컴공 학부생 | 돌아갈 "원래 학습"(수업·교재·자료)이 분명하고 기존 문제 정의의 출처와 일치 |
| 보조 사용자 | CS 면접을 준비하는 취업 준비생 | 아는 개념을 다시 볼 때 빈 곳을 메우는 용도에 맞음 |
| 1차 범위 밖 | 완전 입문자 | 빈틈이 넓어 진단 결과가 "처음부터 전부"가 됨. 진단 기반 보충이 아니라 일반 강의가 필요 |

### 문제

- **원인을 모른다:** 막힌 원인이 지금 개념인지, 그 아래 선수 개념인지 구분하지 못한다.
- **보충의 양이 어긋난다:** 과잉 보충(처음부터 다시)은 시간을 낭비하고, 과소 보충(설명 한 번 듣고 넘어감)은 이해했다는 착각을 만든다.
- **원래 학습으로 돌아오지 못한다:** 검색·영상을 따라 내려가다 어디서 왜 막혔는지 맥락을 잃는다.
- 근거 보강: 기존 근거는 개발자 본인의 경험뿐이다. 학부생 5~10명 대상 짧은 설문·인터뷰로 발생 빈도와 영향을 확인한다. 설문 문항·대상은 아직 정하지 않았다.

### 기존 대안과 한계

| 대안 | 잘하는 것 | 이 문제에서의 한계 |
| --- | --- | --- |
| 범용 챗봇 | 질문한 개념을 바로 설명 | 무엇을 모르는지 먼저 묻지 않음. 설명 속 모르는 개념, 이해 확인 없음, 원래 학습 맥락을 기억하지 않음 |
| 검색·블로그·영상 | 자료량 | 수준·순서 불일치, 탐색 비용, 복귀 어려움 |
| 강의·교재·MOOC | 체계적인 순서 | 고정 순서라 내 빈틈만 골라 볼 수 없음 |
| 사람 튜터·조교 | 진단과 맞춤 보충 | 시간·비용 제약 |

### 차별점

1. **진단이 설명보다 먼저:** 선수 개념 관계를 따라 짧은 확인 문항으로 실제 빈틈을 찾는다.
2. **최소 보충:** 진단된 빈틈만 아래 개념부터 채우고, 이미 아는 개념은 건너뛴다.
3. **이해를 확인해야 다음으로:** 보충마다 적용 문항과 자기 말 설명으로 확인한다. 답변 길이·말솜씨를 이해로 보지 않는다.
4. **원래 학습으로 복귀:** 막힌 지점과 맥락을 저장하고, 보충 후 그 지점에서 다시 시작한다.
5. 보조: 개념 관계를 도식으로 보여 준다.

### 1차 범위

- "원래 학습"은 앱 안의 개념 지도 기반 로드맵 학습과, 막힌 문장·문단을 텍스트로 붙여넣는 입력으로 시작한다.
- PDF·이미지·영상 업로드와 분석은 이후 확장으로 미룬다.

## Level 2. 성공 기준

### 결과 기준 — 학습자에게 일어나야 하는 일

| ID | 기준 | 측정 |
| --- | --- | --- |
| O1 | 막혔던 개념을 이해한다 | 보충 전·후 같은 수준의 다른 문항 정답률과 설명 점수 비교 |
| O2 | 원래 학습으로 돌아간다 | 보충 후 막힌 지점에서 다음 단계를 진행한 비율 |
| O3 | 덜 헤맨다 | 막힘부터 복귀까지 걸린 시간 |
| O4 (선택) | 시간이 지나도 남는다 | 1주 뒤 처음 보는 예시 문항으로 재확인 |

### 작동 기준 — 차별점이 작동하는가

| ID | 차별점 | 측정 |
| --- | --- | --- |
| M1 | 진단 먼저 | 시스템이 찾은 빈틈과 정답 빈틈 비교(recall·precision) |
| M2 | 최소 보충 | 과잉 보충률: 이미 아는 개념을 보충한 비율 |
| M3 | 이해 확인 | AI 판정과 사람 채점의 일치도(Cohen's kappa), 특히 거짓 통과율 |
| M4 | 복귀 | 중단·새로고침 후 막힌 지점과 맥락이 복구되는지 기능 테스트 |

### 품질 하한

- 설명의 사실 정확성. 자체 제작 CS 300문항 시험(CS-300)은 여기에 속한다. 성공 기준이 아니라 필요조건이다.
- 응답 시간과 GPU 운영 조건은 Level 5에서 다룬다.

### 이해 판정 방식

- 혼합형: 자동 채점되는 적용 문항(계산·추적·구분)과 짧은 자기 말 설명(핵심 요소 루브릭)을 **모두** 통과해야 이해로 인정한다.
- 이유: 설명만으로는 LLM 채점이 흔들리고 거짓 통과가 쉽다. 문항만으로는 추측 정답과 개념 연결을 구분하지 못한다. 자동 채점 문항이 거짓 통과를 막는 기준점이다.

### 증명 방법

1. **시뮬레이션 학습자 평가(개발용, 정량):** 선수 개념 일부를 모르게 설정한 가상 학습자로 M1~M3를 수치로 측정한다. 실제 학습자와 다르다는 한계를 함께 밝힌다.
2. **소규모 사람 비교 실험(최종 근거):** 학부생이 제안 시스템과 **같은 모델의 일반 채팅**을 비교 사용하고 O1~O3를 측정한다. 같은 모델을 써서 모델 성능이 아닌 방법의 효과를 분리한다. 인원이 적으므로 효과 크기와 사례로 보고한다.

### 목표 수치 (가설, 예비 실험 후 확정)

| 항목 | 목표 |
| --- | --- |
| 진단 recall (M1) | 0.8 이상 |
| 과잉 보충률 (M2) | 20% 이하 |
| 판정 일치도 (M3) | kappa 0.6 이상 |
| 거짓 통과율 (M3) | 10% 이하 |
| 사후 정답률 (O1) | 일반 채팅 조건보다 높음 |

## Level 3. 핵심 학습 흐름

### 시작점

- E1: 앱 안의 로드맵 소단원 학습 중 막힘.
- E2: 막힌 문장·문단 붙여넣기와 학습 목표 한 줄.

### 흐름

| 단계 | 하는 일 | 연결 기준 |
| --- | --- | --- |
| S1 막힘 감지 | "막혔어요"·질문·소단원 확인 실패로 시작. 복귀 지점(위치·막힌 개념·원문 발췌·시각) 저장 | M4, O3 시작 |
| S2 막힌 개념 특정 | 질문·발췌를 개념 지도의 개념에 연결. 지도 밖이면 지원 범위 밖으로 안내 | — |
| S3 진단 | 선수 개념을 따라 자동 채점 확인 문항. 맞히면 그 아래로 내려가지 않고, 틀리면 한 단계 더 내려감. 결과는 아래부터 정렬된 빈틈 목록 | M1, M2 |
| S4 보충 | 가장 아래 빈틈부터 짧은 설명·예시, 필요하면 도식. 학습자의 원래 예시와 연결 | — |
| S5 이해 확인 | 빈틈마다 혼합형 확인. 실패하면 다른 방식으로 재보충(최대 2회). 그래도 실패하면 미해결로 기록하고 학습자가 진행 여부 선택 | M3 |
| S6 원래 개념 재확인 | 처음 막힌 개념을 혼합형으로 확인 | O1 |
| S7 복귀 | 복귀 지점으로 돌아가 채운 선수 개념과 원문의 연결 요약을 보여 주고 원래 학습 재개 | O2, O3 끝 |
| S8 기록 | 진단·보충·판정 근거·시간 저장, 선택적으로 O4 재확인 예약 | 전체 측정 |

### 공통 규칙

- 단계마다 상태를 저장해 새로고침·재접속 후 같은 단계에서 재개한다.
- 어떤 문항을 틀려 빈틈으로 판단했는지 학습자에게 보여 준다.
- "이미 알아요" 건너뛰기와 "바로 설명" 진단 생략을 허용하되 기록하고 측정에서 분리한다.
- 기존 자유 채팅은 유지한다. 사람 비교 실험의 일반 채팅 조건이 된다.

### 파일럿 결정

- 개념 지도: 파일럿 영역 하나에 대해 사람이 검수한 고정 지도를 쓴다. LLM이 초안을 만들고 개발자가 검수한다. 시뮬레이션 평가의 정답 빈틈을 정하려면 고정 지도가 필요하다.
- 파일럿 영역: 자료구조·알고리즘. 선수 관계가 명확하고 계산·추적 문항으로 자동 채점하기 쉽다.
- 진단 규칙: 위에서 아래로 가지치기 탐색. 진단 문항 최대 5개, 깊이 최대 3단계, 같은 빈틈 보충 최대 2회. 기존 기획서의 초기 실험 후보값을 이은 운영 상한이며 예비 실험 후 조정한다.

## Level 4. 시스템 구조

### 구성

```text
React :5173        개념 지도 로드맵 학습 + [막혔어요] 패널(진단·보충·확인·복귀)
  → Spring :8080   막힘 세션 체크포인트·버전 관리·중계, 측정 기록 보관
    → FastAPI :8001  막힘 흐름 단계 실행(LangGraph), 결정적 채점, LLM 호출
      → vLLM :8000   보충 설명·서술 채점·개념 특정 (모델은 Level 5)
```

### 구성 요소

| 구성 요소 | 위치 | 책임 | 재사용 여부 |
| --- | --- | --- | --- |
| 개념 지도 | 저장소 데이터 파일 | 개념, 선수 관계, 개념별 학습 목표 | 새로 작성(LLM 초안 → 검수) |
| 문항 은행 | 저장소 데이터 파일 | 진단·확인 문항, 정답, 서술 루브릭 | 새로 작성(생성 → 정답 독립 대조 → 검수) |
| 막힘 흐름 엔진 | FastAPI·LangGraph | S1~S8 상태 전환, 요청당 한 단계 | 커리큘럼 단계 실행 패턴 재사용 |
| 결정적 채점기 | FastAPI | 자동 채점 문항 정답 비교. LLM 미사용 | 새로 작성(CS-300 정규화 방식 참고) |
| LLM 역할 | FastAPI → vLLM | ① 개념 특정(지도의 개념 ID로 schema 제한) ② 보충 설명·도식 ③ 서술 루브릭 채점 ④ 복귀 요약 | 채팅·도식·schema 출력 재사용 |
| 막힘 세션 저장소 | Spring | 체크포인트·버전 기반 중복 실행 방지, 측정 기록 | `CurriculumStore` 패턴 재사용 |
| 학습 화면 | React | 개념 지도 로드맵, [막혔어요]·붙여넣기, 진단·확인 UI | 로드맵·채팅 화면 확장 |
| 시뮬레이션 학습자 | 저장소 평가 코드 | 공개 API로 흐름을 끝까지 진행하고 M1~M3 계산 | 새로 작성 |
| 실험 모드 | Spring·React | 참가자 ID, 조건 배정, 기록 분리 | 새로 작성 |

### 원칙

- 진단·적용 문항의 채점은 검수된 정답으로 결정적으로 한다. LLM 판단은 서술 채점에만 남기고 M3로 따로 검증한다.
- 사람과 시뮬레이션 학습자가 같은 공개 API를 사용한다. 시뮬레이션 결과가 실제 시스템의 동작임을 보장한다.
- 단계 실행 API는 커리큘럼과 같은 형태(`{version, input}`을 받아 한 단계 실행 후 저장)를 따른다.

### 바뀌거나 범위에서 빠지는 것

- 하드코딩된 개념 9개 로드맵은 자료구조·알고리즘 개념 지도로 대체한다.
- AI 커리큘럼 초안 기능은 유지하지만 1차 학습 흐름에서는 뺀다.
- 저장은 계속 로컬 JSON이다. DB 전환은 목표 ERD로 남긴다.
- 구현은 AGENTS.md의 PR 크기 규칙에 맞춰 나누며 분할안은 구현 착수 전에 따로 합의한다.

## Level 5. 모델·데이터·평가

### 모델

- 서빙 기본값: Qwen3-8B(추론 활성)를 GPU 1장에서 서빙한다. 나머지 GPU 1장은 시뮬레이션 학습자·데이터 생성·학습에 쓴다.
- 최종 결정: LLM 역할 ①~④별 평가로 정한다. 8B가 기준에 못 미치는 역할이 있을 때만 그 역할에 27B를 고려한다.
- 파인튜닝: 기본 계획에 넣지 않는다. 역할별 평가에서 격차가 측정될 때만 LoRA로 보완한다. 예: 서술 채점 kappa 미달 시 사람 채점 라벨이나 27B 판정을 학습 데이터로 사용.
- 시뮬레이션 학습자: 서빙 모델과 다른 모델을 쓴다. 같은 모델이 양쪽을 맡으면 서로의 말투·오류에 맞춰 점수가 부풀 수 있다.

| 역할 | 필요한 능력 | 확인 방법 |
| --- | --- | --- |
| ① 개념 특정 | 발췌를 개념 ID로 정확히 분류 | 개념 ID를 붙인 발췌 약 50개로 정확도 |
| ② 보충 설명 | 사실에 맞는 한국어 설명, 도식 도구 호출 | CS-300, 도구 호출 성공률 |
| ③ 서술 채점 | 루브릭 항목별로 사람과 같은 판정 | M3 kappa, 거짓 통과율 |
| ④ 복귀 요약 | 짧고 정확한 연결 설명 | 표본 직접 검토 |

## 현재까지의 측정 근거

- 모든 수치는 2026-10-21~23 로컬 측정 1회 결과다. 반복 실행 전이므로 몇 문항 차이는 잡음일 수 있다.
- CS-300은 6개 영역 × 50문항의 자체 제작 시험이다(선택형 240, 계산·과정 추적 단답 60). 문항·응답 원본은 Git에 포함하지 않는 로컬 `codex/model-evaluation/`에 있다.

| 구성 | 전체 | 추적 60 | 출력 토큰 합계 |
| --- | ---: | ---: | ---: |
| Qwen3.5-27B AWQ 기본(온도 0.2, 추론 끔, 384토큰) | 289 | 49 | 15,999 |
| 27B 추론 + 근거 우선(공식 권장값) | 300 | 60 | 447,943 |
| Qwen3-8B AWQ 기본(27B 기본과 같은 조건) | 271 | 33 | 14,202 |
| 8B 근거 우선(지시 한 문장 추가) | 276 | 38 | — |
| 8B 추론(공식 추론 권장값) | 297 | 60 | 120,426 |

- 8B 추론 구성은 추론 활성·권장 샘플링·출력 상한 32,000이 함께 바뀐 결과다.
- 297·300은 천장에 가까워 CS-300만으로 상위 구성 간 차이를 가리기 어렵다. 그래서 모델 결정은 역할별 평가로 한다.
- VRAM: 27B는 GPU 2장(TP=2)에서 각각 약 20.7GB를 점유한다(디스크 가중치 11GB, 나머지는 `--gpu-memory-utilization 0.9`의 KV 캐시 사전 할당). 8B는 GPU 1장에서 가중치·기타 5.82GiB, KV 캐시 14.13GiB를 쓴다.
- vLLM은 시작 시 메모리를 사전 할당하므로 학습 세션이 길어져도 서빙 VRAM이 늘지 않는다. 모델 축소의 실제 이유는 서빙과 학습·실험을 GPU 2장에서 함께 운용하기 위해서다.
